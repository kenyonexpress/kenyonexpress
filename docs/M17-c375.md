## The two error-screen loads

In pass 1, `/product/מלון-5-כוכבים-בטבריה` at 380 (07:35:40 +07) and
`/product/טיפול-פנים-עמוק` at 380 (07:48:38 +07) rendered "משהו השתבש אצלנו"
(`src/app/error.tsx`, the root boundary) with HTTP 200 on the document. Unlike
M17-c363, the probe recorded the console. On both loads the same sequence
appears: a burst of `net::ERR_NETWORK_CHANGED`, `ERR_NAME_NOT_RESOLVED` (and on
the second, `ERR_INTERNET_DISCONNECTED`) on the page's own chunks, fonts and
images, then:

```
ERR console.error: ChunkLoadError: Failed to load chunk /_next/static/immutable/chunks/13p88pe828igi.js from module 695672
ERR console.error: app error boundary:  ChunkLoadError: Failed to load chunk /_next/static/immutable/chunks/13p88pe828igi.js from module 695672
```

So: the HTML arrived, the browser then lost the network while fetching a
lazily loaded chunk, the import rejected, and React's error boundary rendered
the error screen. The same chunk, `13p88pe828igi.js`, failed in both loads,
which fits one lazily imported module on the product page rather than a bad
asset (the chunk loaded fine on the other 200 or so product loads). The error
screen itself is RTL (0 leaks on its 26 elements, overflow 0 px). Both pages
rendered the product at the other widths in pass 1 and at all three widths in
pass 2. `error.tsx` sends the exception to Sentry tagged `boundary=app-error`,
so two events around 00:35:40 and 00:48:38 UTC should be there; not read here
(no valid Sentry token on this machine, BACKLOG #21).

What this means for BACKLOG #26 (the one occurrence in M17-c363, console not
captured): a client-side chunk-load failure now reproduces the exact symptom
(HTTP 200, "משהו השתבש אצלנו", 26 elements) and leaves no server-side error,
which also matches the empty Vercel log of c363. It is the leading candidate.
It is not proven for c363: that load had no network errors recorded because
nothing was recorded. The screenshots and body text of both loads are in
`/tmp/m17-c375/work/errscreen-380-*.png|txt` (not committed).

Not touched: whether a chunk-load failure should show the full "500" screen
rather than a reload prompt is a product decision for Ofir; `src/app/error.tsx`
is outside the freeze but outside this item's scope.
