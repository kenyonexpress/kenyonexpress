## What "real deps" means here
- database: PROBED, HEAD count on `categories` through the admin client (health) and a select (ready). `ok` on both, so the production service key works against Postgres.
- redis: PROBED, the rate limiter (`check_rate_limit` Postgres RPC, plus Upstash PING when configured). `ok`.
- meilisearch: `not_configured`. Meilisearch is paused by owner decision (PROOF RULE 01.11), optional, Postgres ILIKE covers search, and neither route treats it as down.
- r2, cardcom: config presence only by design (`src/lib/health/ready.ts` header): R2 is not enabled on the account, Cardcom has no side-effect-free endpoint.
- Both responses are `cache-control: no-store` and `x-vercel-cache: MISS`, so the 200s are live checks, not cached.
