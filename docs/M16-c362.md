# M16-c362: JSON-LD Product and BreadcrumbList on every product page

Measured 06.11.2026, ~09:35 +07, on the live site
`https://www.kenyonexpress.co.il`. HEAD and `origin/closeout/v1-final` are both
`2960aba00`. M16-c361 could only measure a local build, because production was
in maintenance mode; this is the first M16 run against production.

## Result

**All 82 active product pages emit exactly one `Product` node and exactly one
`BreadcrumbList` node, and both parse.** That is the 80 pages in
`/sitemap/products.xml` plus the two E2E fixtures the sitemap leaves out on
purpose. Each `Product` has a name, a `url` whose path is the page's path, and
an `Offer` with a two-decimal `price > 0` in `ILS` and an `InStock` or
`OutOfStock` availability. Each `BreadcrumbList` has at least two crumbs at
positions 1..n, and its last crumb carries the product's name and path.

Three pages lack one optional field, `Product.image`. None is a code defect:

| Page | Why |
|---|---|
| `/product/מזקקת-ויסקי` | `products.images` is `[]`: ledger entry `no-image:8198e729-...` in `supabase/catalogue-known-issues.json`. Same finding as M16-c361. Picking a photo is the operator's decision. |
| `/product/e2e-test-coupon`, `/product/e2e-test-physical` | Playwright fixtures, deliberately without a picture and kept out of the sitemap (`isE2eFixtureSlug` in `src/lib/seo/sitemap-sections.ts`). |

`buildProductJsonLd` (`src/lib/seo/json-ld.ts`) drops `image` when there is
none and does not invent one. No code changed.

## Probe

`/tmp/m16c362/check.mjs` (not committed). For each URL it follows redirects,
extracts every `<script type="application/ld+json">`, and checks:

- HTTP 200, and the JSON parses
- `Product` x1 and `BreadcrumbList` x1
- `Product.name`, `Product.image`, and `Product.url` with the page's path
- `offers` present: `price` matching `^\d+\.\d{2}$` and `> 0`, `priceCurrency: ILS`, availability `InStock`/`OutOfStock` (or `OutOfStock` with no price)
- at least two crumbs, each with `position == i+1`, a name and an item
- the last crumb's name equals `Product.name`, and its URL has the page's path

Run 1, the 80 `<loc>` URLs exactly as the sitemap lists them (apex host, each
answering `308` to `www`):

```
$ node check.mjs locs.txt
pages=80 ok=79 bad=1 {"offerPrice":80,"offerOOS":0,"aggOffer":0,"noOffer":0,"rating":0,"redirected":80}
Product.url origins: [["https://kenyonexpress.co.il",80]]
BAD /product/מזקקת-ויסקי: Product.image missing
```

Run 2, all 82 active slugs from the database, on `www` directly:


## Recorded, not changed

- **Every URL inside the nodes names the apex host**
  (`https://kenyonexpress.co.il/...`), and so does `<link rel="canonical">`,
  while the apex answers `308` to `www`. The structured data is consistent with
  the canonical and the sitemap, so nothing here contradicts itself, but the
  declared canonical host is one redirect away from the host that serves.
  M11-c362 recorded the same thing for the sitemap and robots. Which host is
  canonical is a Vercel domain / `NEXT_PUBLIC_APP_URL` setting, the operator's
  call.
- **Not checked:** that each `Offer.price` equals the price the page renders
  and the cart charges. The probe asserts shape and sign only.
- No product emits `aggregateRating`. The builder emits it only with at least
  one approved review, so 0 means no product has one yet.
