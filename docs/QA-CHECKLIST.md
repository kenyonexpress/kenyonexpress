# QA Checklist - בדיקה ידנית מלאה

רשימת בדיקה ידנית לכל דפי האתר, מסודרת לפי עדיפות. נבנתה מסקירת קוד בלבד (read-only).
לכל דף: מה אמור לעבוד, איך בודקים, ו-edge cases.

**מקרא עדיפויות:**
- **P0** - קריטי (הכנסה, הזדהות, אבטחה). כשל כאן חוסם משתמשים או חושף סיכון.
- **P1** - ליבה (גלישה, קנייה, ניהול תוכן). כשל פוגע קשות בחוויה.
- **P2** - משני (תצוגה, דפים סטטיים, edge cases נדירים).

**סימונים גלובליים לבדיקה בכל דף:**
- RTL: יישור טקסט, שיקוף אייקונים, תצוגת מספרים/מחירים, שדות `dir="ltr"` (טלפון, מייל, slug, SKU) בתוך הקשר RTL.
- Responsive: mobile / tablet / desktop (בדגש על breakpoints `md:` ו-`lg:`).
- מצבי loading / empty / error בכל דף שטוען נתונים.

## P0 - קריטי

### 1. התחברות - `/login`

**מה אמור לעבוד:** שלוש שיטות התחברות עצמאיות על אותו כרטיס - Google, אימייל+סיסמה, קישור קסם (magic link).

**איך בודקים:**
- [ ] התחברות תקינה עם אימייל+סיסמה מעבירה ליעד (`next`) או ל-`/`.
- [ ] התחברות עם Google עובדת ומחזירה דרך `/auth/callback`.
- [ ] "כניסה ללא סיסמה" חושף טופס magic link; שליחה מציגה "בדקו את תיבת הדואר".
- [ ] קישור "שכחתם סיסמה?" מוביל ל-`/forgot-password`.
- [ ] מיזוג עגלת אורח: הוסף פריטים כאורח, התחבר, ודא שהעגלה נשמרה ומוזגה, וש-cookie האורח נמחק.

**Edge cases:**
- [ ] פרטים שגויים -> "כתובת אימייל או סיסמה שגויים".
- [ ] אימייל שלא אומת -> "כתובת האימייל טרם אומתה".
- [ ] שלוש שגיאות נפרדות (3 states) - ודא ששגיאה בשיטה אחת לא דולפת לאחרת.
- [ ] **פתיחת redirect (אבטחה):** נסה `?next=//evil.com`, `?next=https://evil.com`, `?next=/\evil.com` - חייב ליפול חזרה ל-`/` ולא לנווט החוצה.
- [ ] `?error=auth_callback_error` -> באנר אדום "הכניסה נכשלה".
- [ ] Rate limit: 10 ניסיונות/שעה per-IP -> "יותר מדי ניסיונות כניסה". שים לב: אם ה-RPC נכשל, המערכת "fails open" (מאפשרת מעבר).
- [ ] אין בדיקת אורך סיסמה ב-login (בניגוד ל-signup).

### 2. הרשמה - `/signup`

**מה אמור לעבוד:** יצירת חשבון עם שם מלא, אימייל, טלפון, סיסמה + הרשמה עם Google.

**איך בודקים:**
- [ ] הרשמה תקינה -> מעבר ל-`/signup/confirm` (לא מתחבר אוטומטית, נדרש אימות מייל).
- [ ] `full_name` ו-`phone` נשמרים כ-metadata של המשתמש.

**Edge cases:**
- [ ] אימות טלפון ישראלי: בדוק `050-1234567`, `0501234567`, `+972501234567`, `972521234567`. דחה `123`, מספרים לא תקינים -> "מספר טלפון ישראלי לא תקין".
- [ ] סיסמה: מינימום 8 תווים **וגם** לפחות ספרה אחת. `abcdefgh` עובר HTML5 אך נכשל בשרת ("חייבת להכיל ספרה").
- [ ] שם מלא של תו אחד / רווחים בלבד -> נכשל (min 2 אחרי trim).
- [ ] אימייל כבר רשום -> "כתובת האימייל כבר רשומה".
- [ ] רק שגיאת ה-zod הראשונה מוצגת - בדוק כל שדה בנפרד.
- [ ] Rate limit: 5 הרשמות/שעה per-IP.

### 3. שכחתי סיסמה - `/forgot-password`

**איך בודקים:**
- [ ] שליחה -> הטופס מוחלף בהודעה ירוקה "שלחנו לך קישור לאיפוס".
- [ ] קישור האיפוס במייל מצביע ל-`/auth/callback?next=/reset-password`.

**Edge cases:**
- [ ] **אבטחה (user enumeration):** הודעת הצלחה מוצגת גם אם המייל לא קיים - ודא שאין דליפה על קיום חשבון.
- [ ] אחרי הצלחה הטופס נעלם ולא ניתן לשלוח שוב בלי רענון - ודא שזו התנהגות רצויה.
- [ ] Rate limit: 5/שעה.

### 4. איפוס סיסמה - `/reset-password`

**איך בודקים:**
- [ ] הגעה דרך קישור מייל תקין -> בחירת סיסמה חדשה + אישור -> הצלחה מנתבת ל-`/`.

**Edge cases:**
- [ ] **כניסה ישירה ל-`/reset-password` בלי session שחזור** -> העדכון נכשל; ודא שמוצגת שגיאה (ולא מסך שבור).
- [ ] קישור פג/מנוצל -> העדכון נכשל.
- [ ] סיסמאות לא תואמות -> "הסיסמאות אינן תואמות".
- [ ] אין קישור "חזרה לכניסה" בדף הזה.

### 5. Callback הזדהות - `/auth/callback`

**מה אמור לעבוד:** מטפל ב-OAuth, magic link, ואיפוס סיסמה. מחליף `code` ל-session.

**Edge cases:**
- [ ] Google OAuth: `next` שורד את המעבר דרך Google ונוחת בדף הנכון.
- [ ] קוד לא תקין/פג/מנוצל -> ניתוב ל-`/login?error=auth_callback_error`.
- [ ] היעדר `code` (כניסה ישירה) -> ניתוב לשגיאת login.
- [ ] מיזוג עגלת אורח קורה גם כאן - ודא מיזוג ומחיקת cookie.
- [ ] **`NEXT_PUBLIC_APP_URL` נכון בכל סביבה** (staging/prod) - ערך שגוי שובר את כל ה-OAuth/magic/reset.

### 6. Checkout - `/checkout`

> הערה: קבצי התשלום עצמם (`src/lib/payments/`, `src/server/actions/payments/`) בעבודה ב-session אחר. הבדיקות כאן ברמת הדף בלבד.

**מה אמור לעבוד:** טופס תשלום עם כתובת (אם נדרש), ארנק, קופון, תנאים, ושמירת כרטיס.

**איך בודקים:**
- [ ] רשימת פריטי ההזמנה נכונה; פריטי קופון מציגים "תשלום באתר / יתרה בעסק".
- [ ] כתובת: אם קיימת כתובת שמורה -> סיכום + hidden id; אחרת טופס עריכה עם שדות חובה (שם, עיר, רחוב, מספר).
- [ ] ארנק: שדה מופיע רק אם balance > 0; `max = min(walletBalance, subtotal)`.
- [ ] checkbox "תנאים" חובה; "שמירת כרטיס" מסומן כברירת מחדל.
- [ ] כפתור "מעבר לתשלום מאובטח" -> מצב pending "מעביר לדף תשלום מאובטח...".

**Edge cases:**
- [ ] כניסה ישירה ל-`/checkout` כשלא מחובר / עגלה ריקה -> ניתוב ל-`/cart`.
- [ ] ארנק: הזנת ערך מעל max, שלילי, עשרוני.
- [ ] כל טעינת דף מייצרת `client_ref` חדש (UUID) - בדוק התנהגות idempotency בשליחה חוזרת.
- [ ] מסלול כתובת שמורה מדלג על טופס עריכה (אי אפשר לערוך inline).

### 7. חזרה מתשלום - `/checkout/return`

**מה אמור לעבוד:** קורא `?order_id`, מיישב סטטוס הזמנה, מציג הצלחה/ממתין/כשל.

**איך בודקים:**
- [ ] תשלום מוצלח -> "התשלום הצליח!" + מזהה הזמנה (8 תווים ראשונים) + סכום ששולם.
- [ ] קופונים: כרטיסי קופון עם קוד, תוקף, QR, וקישור שיתוף WhatsApp.
- [ ] cashback: הערה מוצגת רק אם cashback > 0.

**Edge cases:**
- [ ] `order_id` חסר/לא תקין -> 404.
- [ ] מצב pending: `AutoRefresh` מרענן כל 3 שניות - ודא שבסוף מתייצב ושה-interval מתנקה ב-unmount.
- [ ] סטטוס `failed` -> ניתוב ל-`/checkout/failed`.
- [ ] הזמנה בלי קופונים (פיזי בלבד) -> אזור קופונים מוסתר.
- [ ] קופון עם `collect_amount_ils = 0` -> שורת היתרה מוסתרת.
- [ ] ביצועי QR עם קופונים רבים.

### 8. תשלום נכשל - `/checkout/failed`

**איך בודקים:**
- [ ] מציג "התשלום לא הושלם" + "החיוב לא בוצע... העגלה שלך נשמרה".
- [ ] **ודא שהעגלה באמת נשמרת** אחרי כשל (הטענה בקופי) - "חזרה לעגלה" מחזיר לעגלה מלאה.

## P1 - ליבה

### 9. עגלה - `/cart`

**מה אמור לעבוד:** רשימת פריטים, שינוי כמות, הסרה, ריקון, סיכומים, מעבר ל-checkout.

**איך בודקים:**
- [ ] עגלה ריקה -> `CartEmptyState` + קישור לבית.
- [ ] stepper כמות (min 1, max 99), הסרה (פח), "רוקן עגלה".
- [ ] סיכומים: מספר פריטים, subtotal, עמלת פלטפורמה/יתרה לעסק (רק כשמעל 0).
- [ ] מחובר -> כפתור checkout מקשר ל-`/checkout`. לא מחובר -> כפתור התחברות Google (`next=/checkout`).

**Edge cases:**
- [ ] פריט לא זמין -> אזהרה "המוצר אינו זמין"; checkout חסום.
- [ ] **בדיקה חשובה:** כפתור checkout למחובר הוא `<a aria-disabled>` - דפדפנים עדיין מאפשרים קליק על קישור aria-disabled. ודא שהניווט באמת חסום כשיש פריט לא זמין.
- [ ] stepper מוגבל ל-99 בלבד, אין ולידציית מלאי בדף העגלה.
- [ ] קליקים מהירים על כמות בזמן `isPending`.
- [ ] re-hydration של ה-store ב-mount עלול לדרוס שינויים אופטימיים בניווט חזור.

### 10. עמוד מוצר - `/product/[slug]`

**מה אמור לעבוד:** גלריה, פרטי מוצר, בחירת variant, כמות, הוספה לסל, ספק, מוצרים קשורים.

**איך בודקים:**
- [ ] טעינת מוצר פעיל לפי slug; מוצר חסר -> 404.
- [ ] אינדיקטור מלאי, מחיר עם מחיר ישן מחוק + אחוז הנחה.
- [ ] בורר variants: variant אזל = מושבת/עמום. variant יחיד נבחר אוטומטית. אם יש variants ואף אחד לא נבחר -> הוספה לסל חסומה.
- [ ] stepper כמות (min 1, max = מלאי או 99), הוספה לסל -> "נוסף לסל" ל-2 שניות.
- [ ] כפתור משתנה ל"רכוש קופון" לקופונים, "אזל מהמלאי" כשאין מלאי.

**Edge cases:**
- [ ] מוצר עם `kenyon_price` null -> מחיר מוצג ₪0.00.
- [ ] variant עם `stock_quantity` null (נחשב במלאי, max 99) מול 0.
- [ ] slug בעברית (URL-encoding / decodeURIComponent).
- [ ] טקסט קופון "10%" קשיח - ודא התאמה ללוגיקת החיוב בפועל.
- [ ] גלריה: אין תמונות -> placeholder 📦; תמונה יחידה -> אין thumbnails.
- [ ] ספק חסר -> "פרטי הספק יתעדכנו בקרוב".

### 11. חנות / כל המוצרים - `/products`

**מה אמור לעבוד:** גריד עם מיון, עמודים, סינון מחיר, sidebar קטגוריות.

**איך בודקים:**
- [x] כותרת "חנות" + טקסט ספירת תוצאות (סגנון WooCommerce). ‏`h1` = "חנות", והספירה "מציג 1–24 מתוך 61 תוצאות".
- [x] מיון (`?sort=`) מאפס לעמוד 1. ‏`params.delete('page')` ב-`CategoryControlBar`, וארבעת ה-`sort` מחזירים סדר שונה בפועל.
- [x] סינון מחיר (min/max) מאפס עמוד. ‏`pushWith` מוחק `page` בכל שינוי סינון, כולל סוג מוצר.
- [x] Pagination: מוסתר כשעמוד יחיד; prev/next מושבתים בקצוות; שומר sort/min/max. נמדד: ‏`?min=1000` (6 תוצאות) בלי ניווט; עמוד 1 בלי "הקודם"; עמוד 3 בלי "הבא"; ‏`?page=2&sort=price_asc&min=10&max=5000` מעביר את שלושתם לכל קישור.
- [x] מצב ריק -> "לא נמצאו מוצרים התואמים את הבחירה שלך".

**Edge cases:**
- [x] `?page=9999` -> נצמד לעמוד אחרון; `?page=abc` -> עמוד 1. תוקן ב-19.08; ‏`?page=9999` מציג "מציג 49–61 מתוך 61".
- [x] `min`/`max` שליליים/לא מספריים; `min > max` (אין cross-validation -> כנראה תוצאה ריקה). ‏`-5` ו-`abc` נופלים ל-`undefined` ומחזירים את כל 61; ‏`min=100&max=1` מחזיר את המצב הריק בלי ניווט.
- [x] **מחליף תצוגת גריד/רשימה הוא ויזואלי בלבד (לא פעיל)** - סמן אם QA מצפה לתצוגת רשימה. ‏`<span>` עם `aria-hidden`, בלי handler. זהה לחי, ולכן נשאר.

### 12. עמוד קטגוריה - `/category/[slug]`

**מה אמור לעבוד:** כמו החנות אך מסונן לקטגוריה. breadcrumb + sidebar עם קטגוריה פעילה מודגשת.

**איך בודקים:**
- [x] `getCategoryBySlug`; קטגוריה חסרה -> 404. **היה 200.** ראה "‏`/category/[slug]` ענה 200 על slug מת" ב-`STATE.md`; עכשיו `404` באמת, והקטגוריות האמיתיות שמרו על `x-nextjs-postponed: 1`.
- [x] breadcrumb: בית / הורה (אם יש) / קטגוריה נוכחית. שתי חוליות בפועל, כי אין בפרודקשן אף קטגוריה עם הורה.
- [x] אותן בדיקות מיון/מחיר/pagination כמו החנות. אותם רכיבים בדיוק; נמדד על `/category/new` (25 תוצאות, 3 עמודים) והתנהג זהה.

**Edge cases:**
- [x] קטגוריה ללא הורה מול מקוננת (עומק breadcrumb). **‏12 הקטגוריות בפרודקשן כולן `parent_id IS NULL`**, ולכן ענף ההורה קיים בקוד ואינו ניתן להפעלה בנתונים האמיתיים. נבדק בקריאה בלבד.
- [x] קטגוריה לא פעילה (`is_active=false`) - ודא אם `getCategoryBySlug` מסנן פעילות (אחרת קטגוריה מוסתרת עלולה להיטען). מסנן: ‏`.eq('is_active', true)`. אין שורה כזאת בפרודקשן, וכזאת שתיווצר תקבל את אותו `404`.
- [x] קטגוריה ריקה -> מצב ריק, בלי pagination. אין קטגוריה ריקה בקטלוג; ‏`/category/pets?min=100&max=1` מגיע לאותו ענף ומציג את המצב הריק בלי ניווט.

### 13. חיפוש - `/search`

**מה אמור לעבוד:** קורא `?q=`, מחזיר תוצאות מ-`searchProductsServer`. `noindex`.

**איך בודקים:**
- [x] `q` באורך < 2 -> "הקלידו לפחות 2 תווים כדי לחפש".
- [x] תוצאות -> גריד `ProductCard`; תג מנוע "· Meilisearch" מופיע רק ל-Meilisearch. ‏`engine === 'meilisearch' && ...`; מקומית המנוע הוא `database` והתג אכן נעדר.
- [x] אין תוצאות -> "לא נמצאו מוצרים עבור {q}".
- [x] **‏שאילתה של יותר ממילה אחת החזירה 0.** ראה "החיפוש חיפש את כל הביטוי" ב-`STATE.md`: ‏`צימר צפון` החזיר 0 בזמן ש-"צימר שוויץ בצפון" קיים. עכשיו כל מילה נבדקת בנפרד.

**Edge cases:**
- [x] שאילתה של תו אחד מציגה מצב "הקלד 2 תווים" גם אם `?q=` מוגדר. נבדק על `a`, ‏`צ`, ‏`%`, ‏`_`, ‏`\`.
- [x] תווים מיוחדים / עברית / רווחים בלבד (trim לריק). ‏`%20%20%20` → מצב "הקלידו"; ‏`%%` מחזיר ריק ולא את כל הקטלוג, כלומר ה-escaping מחזיק.
- [x] XSS: השאילתה מוצגת ישירות בכותרת (React בורח, אך ודא). ‏`<img src=x onerror=alert(1)>` יוצא כ-`&lt;img ...&gt;` ב-`h1`, ב-`<title>` וב-`meta description`. אפס תגי `<img>` גולמיים בתשובה.

### 14. עמוד הבית - `/`

**מה אמור לעבוד:** Hero, רצועת קטגוריות, benefit bar, מבצעי היום.

**איך בודקים:**
- [x] Hero slider: autoplay/controls, סדר עמודות RTL, קריסה responsive (`lg:`). מכוסה בשני טסטי E2E: ההחזקה על השקופית הראשונה עד אינטראקציה, וההחלפה מהתמונה הסטטית לאנימציה.
