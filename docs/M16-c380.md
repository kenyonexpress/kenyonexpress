# M16-c380: JSON-LD Product and BreadcrumbList on every product page

Measured 07.11.2026, 16:31-16:36 +07 (09:31-09:36 UTC), on the live site
`https://www.kenyonexpress.co.il`. Read-only, no code change. Nothing differs
from M16-c379.

## Result

**All 82 active product pages emit exactly one `Product` node and exactly one
`BreadcrumbList` node, and both parse.** That is the 80 pages in
`/sitemap/products.xml` plus the two E2E fixtures the sitemap leaves out on
purpose. Each `Product` has a name, a `url` whose path is the page's path, and
an `Offer` with a two-decimal `price > 0` in `ILS` and an `InStock` or
`OutOfStock` availability. Each `BreadcrumbList` has at least two crumbs at
positions 1..n, and its last crumb carries the product's name and path.

Three pages lack one optional field, `Product.image`, the same three as in
M16-c370 to M16-c379. None is a code defect:

| Page | Why |
|---|---|
| `/product/מזקקת-ויסקי` | `products.images` is `[]`: ledger entry `no-image:8198e729-...` in `supabase/catalogue-known-issues.json`. Picking a photo is the operator's decision. |
| `/product/e2e-test-coupon`, `/product/e2e-test-physical` | Playwright fixtures, deliberately without a picture and kept out of the sitemap. |

The database agrees: these three rows, and no other active row, have
`images = []` (read directly this cycle). `buildProductJsonLd`
(`src/lib/seo/json-ld.ts`) drops `image` when there is none and does not invent
one.

Both nodes are built in `src/app/(store)/product/[slug]/page.tsx` from the
values the page renders (`buildProductJsonLd`, `buildBreadcrumbJsonLd`,
`jsonLdScript` in `src/lib/seo/json-ld.ts`) and emitted as two
`<script type="application/ld+json">` tags beside the visible breadcrumb. The
breadcrumb trail is the same `categoryTrail` the visible `<nav>` renders.

## Probe

`/tmp/m16c380/check.mjs`, the M16-c373 to c379 probe byte for byte (copied,
not committed). For each URL it follows redirects, extracts every
`<script type="application/ld+json">`, and checks:

- HTTP 200, and the JSON parses
- `Product` x1 and `BreadcrumbList` x1
- `Product.name`, `Product.image`, and `Product.url` with the page's path
- `offers` present: `price` matching `^\d+\.\d{2}$` and `> 0`, `priceCurrency: ILS`, availability `InStock`/`OutOfStock` (or `OutOfStock` with no price)
- at least two crumbs, each with `position == i+1`, a name and an item
- the last crumb's name equals `Product.name`, and its URL has the page's path

Run 1, first attempt (09:33:20-09:34:52Z), the 80 `<loc>` URLs exactly as the
sitemap lists them (apex host, each answering `308` to `www`). Eight fetches
never reached the site: two `fetch failed` and six `terminated` at the socket,
on the measuring Mac, no HTTP status at all. A different eight pages than in
