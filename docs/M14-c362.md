# M14-c362: Sentry release matches HEAD

Measured 06.11.2026, 08:44-08:50 +07, against production
`www.kenyonexpress.co.il`. Base HEAD `29a09d12a`. No code change.

## Result

**The release tag matches HEAD on every runtime.** HEAD, the branch on origin
and the deployment behind the production alias are the same commit,
`29a09d12aedac2926a9a0bf0341cab196946db0f`, and the live client bundle has that
SHA baked in as its Sentry release.

**Sentry still has no release object for it.** The build's
`sentry-cli releases new` and the source-map upload both fail with
`Invalid token (http status: 401)`, as in M14-c361, M14-c111 and BACKLOG #21.
Events carry the right `release` string, but Sentry has no release entity and
no source maps, so production stack traces stay minified. The fix is unchanged
and is Ofir's: a new `SENTRY_AUTH_TOKEN` in Vercel Production with the
`project:releases` and `org:read` scopes, created in the Sentry UI. The
variable in Vercel is 51 days old. That gap does not affect this item's check,
which compares the tag against HEAD.

The match is for `29a09d12a`. The commit that records this item moves HEAD and
triggers a new production build, whose release will be that new SHA by the
same mechanism.
