## 1. תקנון (תנאי שימוש)

### 1.1 תוכן מינימלי לבדיקה

- [ ] זהות העוסק (שם, ח.פ./ע.מ., כתובת, יצירת קשר)
- [ ] תיאור השירות: פלטפורמה המחברת לקוחות לספקים
- [ ] מודל קופון: שולם באתר (`coupon_price`) + יתרה בבית העסק; חלק פלטפורמה/ספק לפי `platform_percent` (בלי להטעות)
- [ ] מודל פיזי: תשלום באתר, משלוח/איסוף לפי הספק
- [ ] ארנק: קרדיט פנימי בלבד, לא יוצא מהמערכת
- [ ] אחריות תיאור העסקה מול הספק מול הפלטפורמה (ניסוח מדויק עם counsel)
- [ ] קניין רוחני, הגבלת אחריות, דין שיפוט
- [ ] שינוי תקנון: איך מודיעים

### 1.2 התאמה למוצר

התקנון חייב להתאים למודל Escrow הפנימי 2026-07-27 (held עד מימוש).  
אסור נוסח שמבטיח "נאמן חיצוני" או עמלה קבועה 5%/10%.

## 2. מדיניות פרטיות

### 2.1 נושאים לכיסוי

- [ ] אילו נתונים נאספים (חשבון Google, הזמנות, קופונים, ארנק, לוגים טכניים)
- [ ] מטרות עיבוד (אספקה, תמיכה, מניעת הונאה, שיווק בהסכמה)
- [ ] מעבדים: Supabase, Vercel, Cardcom, Resend, R2, אנליטיקה, Meta/Google אם מחוברים
- [ ] עוגיות / SDK (Consent mode לפי ייעוץ)
- [ ] זכויות משתמש (עיון, תיקון, מחיקה בגבולות חוק)
- [ ] שמירת מידע (הזמנות/חשבוניות מול מחיקת פרופיל)
- [ ] יצירת קשר לדמוי פרטיות
- [ ] העברות מחוץ לישראל אם רלוונטי (ספקי ענן)

### 2.2 שיווק

- [ ] אימייל/WhatsApp פרסומי: opt-in מפורש + הסרה (חוק התקשורת 30א)
- [ ] ראיות ב-`consent_events`
- [ ] Transactional (אישור הזמנה, קופון, QR): לא דורש opt-in שיווקי; כן מכבד suppression

## 3. חשבונית מס (חשבונית מס / חשבונית מס קבלה)

### 3.1 עקרון תפעולי

חיוב הלקוח באתר הוא עסקת עוסק מול לקוח (לפי מבנה החברה מול counsel).  
חובה להנפיק מסמך מס כדין עבור הסכום שנגבה באתר.

### 3.2 Checklist מוצר/ops

- [ ] ספק חשבוניות מוגדר (תוכנה מורשית / רואה חשבון / אינטגרציה)
- [ ] מונפקת חשבונית מס (או מסמך מתאים) על סכום ששולם באתר ב-Cardcom
- [ ] פרטי עוסק על המסמך תקינים
- [ ] מספר הזמנה / אסמכתא מקשרים להזמנה במערכת
- [ ] עותק ללקוח (מייל / האזור האישי) בתוך לוחות הזמנים החוקיים
- [ ] ארכיון מסמכים לפי תקופת הוראות מס
- [ ] החזר: מסמך זיכוי מתאים
- [ ] סכום היתרה בבית העסק: **לא** מוצג כאילו נגבה ע"י KE; זה תשלום מול הספק בקופה

### 3.3 מה לא לערבב

| סכום | על חשבונית KE? |
|---|---|
| `coupon_price` / תשלום אתר | כן (לפי מבנה העוסק) |
| יתרה שנגבית בעסק | לא כהכנסת KE |
| קאשבק ארנק | לפי ייעוץ (זיכוי פנימי ≠ חשבונית רגילה בהכרח) |

## 4. חוק הגנת הצרכן: כללי קופונים

רשימת בדיקה מוצרית (ליישור עם counsel; לא מחליף את החוק):

### 4.1 גילוי לפני רכישה (PDP + checkout)

- [ ] מחיר ששולם באתר ברור
- [ ] יתרה לתשלום בבית העסק ברורה (אם קיימת)
- [ ] תוקף הקופון / תאריך אחרון למימוש
- [ ] שם בית העסק / מיקום רלוונטי
- [ ] מגבלות (כשרות, סופ״ש, תורים, למימוש חד-פעמי)
- [ ] מדיניות ביטול לפני מימוש

### 4.2 אחרי רכישה

- [ ] מסמך/מייל אישור עם הפרטים המהותיים (transactional)
- [ ] קוד + דרך להצגת QR באזור האישי
- [ ] שמירת ראיה ל-`wording_version` של הגילוי אם נדרש

### 4.3 ביטול והחזר

- [ ] חלון ביטול לפי סוג העסקה (דיגיטלי / שירות עתידי) מנוסח בתקנון ובמסך
- [ ] קופון שלא מומש: מסלול ביטול/החזר מוגדר ב-RUNBOOK
- [ ] קופון שמומש: אין הבטחת החזר מלא אוטומטי
- [ ] פקיעת תוקף: מדיניות זיכוי ארנק (C6) מפורסמת או מבוטלת במפורש אחרי ייעוץ

### 4.4 איסורים שיווקיים נפוצים לבדיקה

- [ ] אין מחיר מטעה (מחיר "לפני" בלי בסיס)
- [ ] אין יצירת דחיפות פיקטיבית
- [ ] אין הסתרת יתרת תשלום בקופה
- [ ] פרסום בוואטסאפ/מייל רק עם הסכמה מתאימה
