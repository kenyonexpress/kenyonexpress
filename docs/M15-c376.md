## The one dirty load in pass 1

`/product/צימר-שוויץ-בצפון` at 380, the nineteenth of pass 1's 22 loads, at
about 02:12:50 UTC. The HTML document itself answered 200 and the page
rendered its `<h1>` ("צימר שוויץ בצפון"). Then every subresource still in
flight failed on the client side:

```
$ awk '/צימר-שוויץ-בצפון @380/{p=1;print;next} /^\//{p=0} p' run1-prod.txt | sort | uniq -c   (abridged)
  22 console: Failed to load resource: net::ERR_NAME_NOT_RESOLVED
   5 console: Failed to load resource: net::ERR_NETWORK_CHANGED
   2 requestfailed: script net::ERR_NETWORK_CHANGED  .../_next/static/immutable/chunks/*.js
  14 requestfailed: script net::ERR_NAME_NOT_RESOLVED .../_next/static/immutable/chunks/*.js
   (the remaining 11: fonts, /images/logo.webp and /_next/image?url=... on the same two codes)
```

`ERR_NETWORK_CHANGED` is Chromium's own signal that the host's network
configuration changed while requests were open; `ERR_NAME_NOT_RESOLVED` for
`www.kenyonexpress.co.il`, a name that resolved for the eighteen loads before
and the three after, is the DNS path going away on the probing machine. No
response with a status code is involved (0 responses >= 400 in that load),
and the very next load, `/product/צימר-שוויץ-בצפון` at 1440, is clean. The
Mac's unified log for the window returned nothing for `configd`,
`mDNSResponder` or `wifid`, as in M15-c375, so the corroboration is
Chromium's error codes and the clean loads on either side. The 6 broken
images in that load are the image requests that never resolved. The 2
warnings in that load are the usual unused-preload notice for `logo.webp`
and `2x0yntgphzrdv.css`.

Passes 2 and 3, full repeats on the same sample, log 0 errors on all 44
loads, including `/product/צימר-שוויץ-בצפון` at 380 twice.
