## 0. מה הספק חייב להבין לפני חתימה

| נושא | מסר לספק |
|---|---|
| קופון | הלקוח משלם חלק באתר; **היתרה נגבית אצלך בקופה** בזמן הסריקה |
| כסף מהאתר על קופון | נשאר בפלטפורמה; **אין העברה אוטומטית אליך על קופון** |
| פיזי | הלקוח משלם מלא באתר; תקבל payout לפי האחוז שסוכם במוצר (אחרי אישור ואימות) |
| סריקה | חובה אונליין; כל סריקה חד-פעמית |

אין להשתמש במילים: נאמן, Escrow, J5, "כסף מוחזק אצלנו עבורך על הקופון".

## 1. מסמכים (לפני אישור)

### 1.1 חובה לאישור

| מסמך / שדה | הערות |
|---|---|
| שם עסק בעברית | כפי שיופיע באתר |
| ח.פ / עוסק מורשה | העתק ברור |
| טלפון נייד + אימייל | לאימות ולהתראות |
| כתובת מלאה + עיר | לתצוגה וניווט |
| לוגו | לקטלוג |
| איש קשר בעלים | מי חותם על ההסכם |

### 1.2 חובה לפני payout פיזי (לא חוסם סריקה)

| מסמך | הערות |
|---|---|
| פרטי בנק (בנק, סניף, חשבון, שם מוטב) | תואם לעוסק |
| אישור ניהול חשבון / שיק מבוטל | לפי מדיניות פנימית |
| חתימה על הסכם ספק | ראה סעיף 2 |

קבצים: העלאה ל-Storage פרטי (רק admin + בעלים).

## 2. הסכם

1. שלח לספק את טיוטת ההסכם:

```
docs/SUPPLIER-AGREEMENT-DRAFT.md
```

2. ודא שההסכם כולל במפורש: מודל קופון (יתרה בעסק, אין payout קופון מהפלטפורמה), פיזי, סריקה חד-פעמית, ביטולים.
3. קבל חתימה (דיגיטלית או סרוקה) + תאריך.
4. שמור בתיק הספק באדמין.

**לא ייעוץ משפטי.** נוסח סופי אחרי עו"ד.

## 3. הגדרה במערכת (אדמין)

### 3.1 אישור בקשה

```text
הגשה באתר / טופס
  → סטטוס pending
  → אדמין בודק מסמכים
  → approved
       → נוצרת שורת suppliers
       → נוצר supplier_members(owner) למשתמש החותם
       → מייל welcome בעברית
  → או rejected + סיבה (cooldown להגשה מחדש)
```

### 3.2 אחרי אישור

1. מלא פרופיל ספק: תיאור קצר, שעות, וואטסאפ, lat/lng, קישור Waze.
2. הזן פרטי בנק אם יש מוצרים פיזיים בקרוב.
3. צור משתמש סורק (תפקיד `scanner`) לטלפון של הקופה / מנהל משמרת.
4. צור **מוצר טסט** (קופון במחיר נמוך) במצב לא מפורסם / קטגוריית בדיקות.
5. קשר את המוצר לספק הנכון.

### 3.3 מוצר ראשון אמיתי

השתמש במדריך:

```
docs/ADMIN-USER-GUIDE.md
```

חובה: `platform_percent`, מחיר קופון או מחיר מלא, גילוי יתרה בעסק ב-PDP.

## 4. הדרכת סריקה

### 4.1 מה הספק צריך במקום

- טלפון/טאבלט עם מצלמה + אינטרנט  
- התחברות לפורטל ספק או לאפליקציה (מצב ספק)  
- הרשאת מצלמה  

### 4.2 תרגול (לפני עלייה לאוויר)

1. אדמין קונה את מוצר הטסט (או מנפיק שובר בדיקה בסביבת staging).
2. מציגים לספק את מסך ה-QR של הלקוח.
3. הספק פותח **סריקה** → מצלם → מקבל מסך הצלחה בעברית.
4. במסך ההצלחה מופיעה **היתרה לגבייה מהלקוח בקופה** (אם יש).
5. מנסים סריקה שנייה על אותו קוד → חייבים לקבל "כבר מומש".

### 4.3 כללי הפעלה לצוות הקופה

| מצב | מה עושים |
|---|---|
| הצלחה | גובים יתרה (אם מוצגת) ומספקים את השירות |
| כבר מומש | לא נותנים שירות נוסף על אותו קוד; מפנים לתמיכה אם הלקוח מתלונן |
| לא שייך לעסק | מסרבים; לא מנסים "לעקוף" |
| אין אינטרנט | לא מממשים על אמון; ממתינים לחיבור או מתקשרים לתמיכה |
| פג תוקף | מסבירים ללקוח; מפנים לביטול/תמיכה לפי מדיניות |

### 4.4 אפליקציה (כשזמינה)

אותו תהליך במצב Supplier באפ (Expo): מצלמה → redeem אונליין.  
פירוט טכני: `ARCHITECTURE-MOBILE-APP.md` §6.
