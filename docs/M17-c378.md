pages at 380, 768 or 1440. Unchanged since M17-c377, which covered the whole
sitemap; this run is the per-cycle sample.**

identical (`diff` of the per-load lines is empty):

- 0 elements get `direction: ltr` from CSS, other than the 20 numeric discount
  badges on `/`.
- Horizontal overflow is 0 px on every load.
- 36 of 36 loads: HTTP 200, real `h1`, `errors=0` (0 console errors, 0
  `pageerror`, 0 responses >= 400, 0 failed requests). 0 failed navigation
  attempts, 0 unmeasured, 0 error screens. No network drop this time.

## What computes LTR, and why each is not a text leak

|---|---|---|---|---|

| `a[dir="ltr"]` supplier phone link | 3 of the 5 product pages (`demo-professional-service`, `ארוחה-זוגית-…`, `demo-gaming-console`) | 1 each | `052-4635550` (2 pages), `972524635550` (1) | Deliberate. A phone number is Latin digits. |
| `input[type=email][dir="ltr"]`, footer newsletter | every page, visible at 1440 | 1 | Hebrew placeholder `הזן כתובת אימייל`, `text-align: start` | Known exception, BACKLOG #25. Not changed: `src/components/layout` is frozen. |

and in both passes. `barbecue-2` and `pampers-premium-care-diaper-pants-medium`

## Probe

`/tmp/m17-c378/work/probe.cjs` (Playwright Chromium, locale he-IL, not
committed). It is M17-c377's probe with one change: the output directory in
the error-screen screenshot path (`sed` over the `/tmp/m17-c377` prefix). The
checks and the navigation retry are untouched.

Each page loads, waits 3 s, then scrolls 10 x 1200 px so lazy sections mount.
It walks every element in `body` outside `svg` (347 to 967 per load).
Requests to PostHog were aborted so the probe stays out of product analytics.
Each pass ran the 6 pages in one Chromium instance; pass 1 took 3.8 min,
pass 2 took 4.1 min.
