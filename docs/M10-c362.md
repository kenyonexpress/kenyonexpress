## 218: the live blocker

```
profiles_has_supplier_id          false
fn_reads_new_supplier_id          true
profile triggers                  audit_profiles, enforce_profile_ban_columns,
                                  enforce_profile_privilege_columns (enabled, BEFORE UPDATE ROW),
                                  ensure_wallet_account
authenticated UPDATE on profiles  table-wide = true
  wallet_balance_agorot           true
  role                            true
  full_name                       true
profiles rows / last updated_at   359 / 2026-11-04 19:25 UTC
auth.users since launch           0
orders since launch               0
```

The production body of `enforce_profile_privilege_columns` still ends with
`IF NEW.supplier_id IS DISTINCT FROM OLD.supplier_id`, and `profiles` has no
`supplier_id` column. The service-role branch and the admin branch return
before that line, so the callers that reach it are signed-in customers
updating their own row. PL/pgSQL resolves the field at run time and raises
`42703`.

What that means at HEAD:

- `src/server/actions/account.ts:67` saves name and phone with the
  request-scoped client. It is the only customer-session `UPDATE` on
  `profiles` in `src`. Every save returns `שמירת הפרטים נכשלה`.
- The other writers (`auth.ts`, `otp-sign-in.ts`, `guest-orders.ts`,
  `anonymize-user-data.ts`) use the admin client and are not affected.
  Sign-in, guest checkout and account deletion do not go through this path.
- `authenticated` holds table-wide `UPDATE` on `profiles`, including
  `wallet_balance_agorot`. Today the broken trigger is what stops a customer
  writing that column, because it fails every customer update. **Do not
  hot-fix the function on its own.** 218 narrows the grant to
  `(full_name, phone)` and fixes the function in one transaction, and the two
  have to land together.

No customer has hit this on the live site yet as far as the data shows: no
new users and no orders since launch, and no profile row has been updated
since 04.11.

**Not measured:** the failure was not reproduced in this run. A rehearsal
needs a transaction on production that impersonates a customer, and this item
is read only. The evidence is the function body, the missing column and the
trigger state above, plus the rolled-back reproduction recorded in the header
of 218 itself (09.09) and in M05-c1 (25.09).
