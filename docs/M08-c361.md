## Reading

- **Performance.** The devtools figure applies the stated mobile conditions (4x CPU, 150 ms RTT, 1.6 Mbps) for real: LCP 1.7-1.8 s, TBT under 40 ms, CLS at most 0.003 on both pages. The simulated figure spreads 16 points on an unchanged build because Lantern's LCP graph against localhost holds the whole initial script pile. FCP is a steady 1.81 s in every simulated run and only the projected LCP moves (3.2 to 6.5 s). This is the same pattern recorded in `docs/LIGHTHOUSE-AUDIT.md` and `docs/V08-lighthouse.md`. Both numbers are logged above; devtools is the one to quote.
- **Accessibility 100, SEO 100** on both pages, in every run.
- **Best Practices 96** comes from one audit, `errors-in-console`, and the cause is in the local environment, not the code. The four errors are the same on both pages:

```
network  | 404 | http://localhost:3471/_vercel/insights/script.js
network  | 404 | http://localhost:3471/_vercel/speed-insights/script.js
security | Refused to execute script from '/_vercel/insights/script.js' because its MIME type ('text/plain') is not executable
security | Refused to execute script from '/_vercel/speed-insights/script.js' because its MIME type ('text/plain') is not executable
```

  `src/app/layout.tsx:230` renders the two Vercel tags only when `process.env.VERCEL === '1'`, and that is correct. The local `.env.production` (pulled from Vercel, untracked) contains `VERCEL="1"`, and Next loads it for `next build`/`next start`, so the local build renders the tags without Vercel's `/_vercel/*` rewrite behind them. On Vercel the rewrite exists and the scripts load. Nothing needs fixing in code, and `layout.tsx` is frozen anyway. To measure BP 100 locally, build with `VERCEL=` exported, which overrides the file value.
