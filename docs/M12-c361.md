# M12-c361: is robots.txt production-safe?

Run 2026-11-05 on `closeout/v1-final`, base HEAD `6929fb452`.

**Answer: yes, and it is a little tighter now.** Production serves the
storefront rules, not a staging `Disallow: /`. Every page where the URL is the
credential is blocked, every authenticated area is blocked, and the sitemap line
is there. Three noindex routes that robots.txt didn't list were added: two write
on GET from a token, and one is a supplier screen. This doesn't affect
production until the next deploy, and nothing was deployed.

## Route sweep: every top-level segment in `src/app` against the disallow list

Segments not in the list, and why they are fine:
`/mfa /admin-mfa /signup /offline /s/[id]` set noindex, and `/dev/*` calls
`notFound()` in production. `/r/[code]` and `/c/[code]` are rate-limited
redirects, and the remaining segments are public storefront pages.

**Added (src/app/robots.ts):**

- `/newsletter/`: `confirm` and `unsubscribe` run their write *on load*
  from `?token=` (RFC 8058 one-click). A crawler that follows a leaked link
  confirms or unsubscribes somebody. Both already set noindex, but noindex only
  works after the fetch, and the fetch is what does the write.
- `/partner/`: `/partner/redeem`, the coupon-partner camera screen, which
  needs a supplier session. This makes it consistent with `/supplier/`.
- `/dev/`: already `notFound()` in production. It's listed so that a
  `NODE_ENV` slip doesn't get crawled.

`sitemap-robots-agree.test.ts` stays green, so no sitemap URL falls under a
new disallow.
