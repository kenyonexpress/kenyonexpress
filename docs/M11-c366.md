# M11-c366: is sitemap.xml fresh and reachable?

Run 2026-11-06 on `closeout/v1-final`, base HEAD `3481af47a`. Read only: no code
change, no production write, nothing deployed.

**Answer: yes to both, measured on production. Nothing changed since M11-c365
(same day, about an hour and fifty minutes earlier): every file is the same size
and the DB sets are the same.**

1. **Reachable: yes.** `www.kenyonexpress.co.il` serves the index and all five
   section files as `200 application/xml`, and all six pass `xmllint`. All 162
   URLs listed in them return 200.
2. **Fresh: yes, an exact match.** Every active product, category and supplier
   in the production DB is in the sitemap, and nothing else is. The only rows
   left out are the four E2E fixtures, which are filtered on purpose. All 130
   `<lastmod>` values on those three sections match `updated_at` to the
   millisecond. The newest row in the DB (a product, 00:24:47 UTC) is the newest
   `<lastmod>` in the file. No catalogue row has been updated since then.
3. **Still open: BACKLOG #23.** The sitemap, `robots.txt` and the home page
   canonical name the apex host (`https://kenyonexpress.co.il`), and the apex
   answers `308` to `www`. So the advertised sitemap URL and each of the 162
   `<loc>` values reach their page through one redirect. Nothing is
   unreachable, but Search Console reports such URLs as "Page with redirect".
   The fix is a Vercel env value or a domain swap plus a production rebuild, so
   it stays Ofir's.
