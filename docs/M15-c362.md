# M15-c362: no console errors on / and a product sample

Measured 06.11.2026, 08:55 to 09:15 +07, on the live site
`https://www.kenyonexpress.co.il`. Production is out of maintenance mode, so
this is the first M15 run that measures the real site and not a local build.

## Result

**Production logs no console errors on / or on five product pages, at 380 and
1440. It did not when the run started.** The first pass found 92 error entries:
every one was a `/_next/image` request answering 400, and 46 thumbnails were
broken across the 12 page loads. One commit fixed it, and the second pass on the
new deployment found 0.

| | Before (`dpl_9hrVZFeA8AmUFpXry2VvcnTscG5W`) | After (`dpl_13QNLJDsVFZTGFoWweT84iDesCG4`, `f9a0234e6`) |

## Cause

40 active products store 52 distinct `/images/cdn/wp/<hash>.webp` paths in
`products.images`. Those files were committed on `main` in `f28bbc0a6`
(19.10.2026) and never reached `closeout/v1-final`, which is the branch
production deploys from. The source file answered 404, so Vercel's optimizer
answered 400:

```
$ curl -s -D - "https://www.kenyonexpress.co.il/_next/image?url=%2Fimages%2Fcdn%2Fwp%2F18%2F189b3644...9004.webp&w=256&q=75"
HTTP/2 400
x-vercel-error: INVALID_IMAGE_OPTIMIZE_REQUEST
$ curl -s -o /dev/null -w "%{http_code}" https://www.kenyonexpress.co.il/images/cdn/wp/18/189b3644...9004.webp
404
```

Every local path the catalogue references, checked against HEAD and
`origin/main` (101 distinct status+path pairs, all from `products.images`; no
other table holds a `/images/cdn/` path):

```
  52 active head=MISSING main=yes /images/cdn/wp
  33 active head=present main=yes /images/products, /images/categories, /images/hero
  12 archived head=present main=yes /images/products
   4 draft head=present main=yes /images/products
```

## Fix

`git checkout origin/main -- <52 paths>`: the 52 base files the database
references, 2.56 MB, under `public/images/cdn/wp/`. `main` carries 565 files
there (113 images, five renditions each, 22.8 MB). The other 513 are not
restored, because nothing on this branch requests a `.card`, `.thumb` or `.og`
rendition and no row points at the other 61 base files. All 52 are WebP, and
`node scripts/asset-gate.mjs` is clean. No file under `src/` changed.

After the deploy, all 52 answer on production:

```
$ sed 's#^public#https://www.kenyonexpress.co.il#' restore.txt | xargs -P 8 -I{} curl -s -o /dev/null -w "%{http_code} %{content_type}\n" {} | sort | uniq -c
  52 200 image/webp
```

## M15-c361 was wrong about one entry

M15-c361 recorded one `/_next/image` 404 on / at 1440 and classed it as
local-only, on the grounds that `images.loader: 'custom'` disables the local
optimizer. This branch's `next.config.ts` sets no loader, and `pnpm start`
answers `/_next/image` 200 `image/avif`. That 404 was
`189b3644...9004.webp`, one of these 52 missing files. Production was in
maintenance mode that day, so the defect could not be seen there.

in `src/app/layout.tsx`, which is frozen.
