# M16-c361: JSON-LD Product and BreadcrumbList on every product page

Measured 05.11.2026, ~04:45 +07, against the `pnpm build` of `18624c96a`
served by `PORT=3311 pnpm start` (listener PID 58758, stopped by PID
afterwards). HEAD is `19d34ded2`. `git diff --stat 18624c96a HEAD -- src
next.config.ts` is empty, so this build is the current code. Production answers
503 on every route under `MAINTENANCE_MODE` and could not be measured.

## Result

**All 88 product pages in `/sitemap/products.xml` emit exactly one `Product`
node and exactly one `BreadcrumbList` node, and both parse.** Each `Product`
has a name and an `Offer` with a positive `price` in `ILS`. Each
`BreadcrumbList` has positions 1..n, and its last crumb carries the product's
name and URL.

One page fails on one optional field. This is a known catalogue gap and not a
code defect:

| Page | Missing | Why |
|---|---|---|
| `/product/מזקקת-ויסקי` | `Product.image` | `products.images` is `[]`. This is ledger entry `no-image:8198e729-...` in `supabase/catalogue-known-issues.json`. The old site had no image for wp post 6230 either (`wp_import/normalized/products.json`). Picking a photo is the operator's decision. `buildProductJsonLd` drops `image` when there is none rather than inventing one, and that is the correct output. |

I made no code change. The emitter is `src/lib/seo/json-ld.ts`
(`buildProductJsonLd`, `buildBreadcrumbJsonLd`), and the product page is
frozen.

The URLs inside the nodes read `http://localhost:3417`, because
`NEXT_PUBLIC_APP_URL` is baked in at build time (memory
site-url-baked-at-build-time). A production build bakes in the real origin.

## Probe

`/tmp/m16/check.mjs` (38 lines, not committed). It fetches every
`/product/*` path from the local `/sitemap/products.xml`, extracts each
`<script type="application/ld+json">` and checks the following:

- HTTP 200
- the JSON parses
- `Product` x1 and `BreadcrumbList` x1
- `Product.name` and `Product.image` are present
- `offers` is present, with `price > 0` and `priceCurrency: ILS` (or `OutOfStock` with no price)
- each crumb has `position == i+1`, a name and an item
- the last crumb's name equals `Product.name`, and its URL ends with the page path
