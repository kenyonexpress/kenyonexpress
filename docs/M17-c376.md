Measured 07.11.2026, 09:34 to 10:09 +07 (02:34 to 03:09 UTC), against
`https://www.kenyonexpress.co.il`. Read-only: no code changed. `src/`,
`public/`, `messages/` and `supabase/` are unchanged since M17-c375

## Result

**No Hebrew text renders left-to-right on `/` or on 75 product pages, at 380,
768 or 1440. Unchanged since M17-c375, on a sample five pages wider.**

Two passes. Pass 1 covered all 228 loads (76 pages x 3 widths) with 0
unmeasured; the Mac's network dropped again during it (see "The network during
pass 1"), so 5 loads showed the site's error screen and 14 more had failed
requests. Pass 2 re-ran every page that any of those touched (16 pages, 48
loads) once the network was stable: all 48 answered HTTP 200 with their real
`h1`, 0 navigation failures, 47 of 48 `errors=0` (the other had two cancelled
duplicate image requests). Taking pass 2 where it ran and pass 1 elsewhere,
every one of the 228 page-width cells has a clean measurement:

- `<html dir="rtl" lang="he">`, and `body` computes `direction: rtl`, 228 of 228.
- 0 visible elements whose own text contains Hebrew compute `direction: ltr`
  (89 to 197 Hebrew text elements per load).
- 0 Hebrew text elements compute `text-align: left`, or `start` under LTR.
- 0 elements get `direction: ltr` from CSS, other than the 20 numeric discount
  badges on `/`.
- Horizontal overflow is 0 px on every load, including the 5 error-screen
  loads and the 14 loads with network errors in pass 1.
- Pass 1: 204 of 228 loads printed `errors=0`; 5 had only cancelled duplicate
  image requests (`net::ERR_ABORTED`); 19 had network failures on the probing
  Mac (5 of them ending in the error screen). Pass 2: 47 of 48 `errors=0`.

Changed against M17-c375:

- **The error screen of BACKLOG #26 appeared five times, all with the same
  cause as in c375: a `ChunkLoadError` in the browser after the Mac's network

- Pass 1 was faster than c375 (21.5 min against 33) with 7 failed navigation

Carried over from M17-c375:
