## 3. Decisions taken alone

- **Did not restart or resize the production database.** A restart (`POST /v1/projects/{ref}/restart`) or a disk resize is an intervention on production infrastructure, outside a measurement item, and the disk resize costs money. The project disk is 2 GB and its utilization query also fails, so a full disk is one possible cause. That is a guess, not a measurement.
- **Did not make the build tolerate a dead DB to get a number.** A build that renders an empty catalogue gives Lighthouse scores for pages that don't exist (product routes would 404), and those numbers would be worthless.

## 4. Known structural gap for the next run (from the code, not measured this run)

`/cart`, `/checkout` and `/account/` are in the `disallow` list in `src/app/robots.ts`, and `scripts/lh-seven.sh` records that `/cart` and `/checkout` score ~61 on SEO because `is-crawlable` fails, on purpose. Lighthouse's `is-crawlable` fails on robots.txt disallow as well as on a noindex meta tag. So SEO >= 90 on those three routes can only be reached by making a cart, a checkout and a logged-in account indexable. That is a privacy and SEO defect, and the next run should not do it. Also, `/checkout` with an empty cart redirects to `/cart`, and `/account` without a session redirects to login, so both need a seeded session to measure the real page.
