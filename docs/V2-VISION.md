## 1. ארבעת עמודי V2

### 1.1 מנועי המלצות (ML / ranking)

| | |
|---|---|
| **מה** | דילים מומלצים בדף הבית, "עוד כמו זה" במוצר, מייל/פוש מותאם |
| **איך (MVP)** | קודם rules + collaborative filtering קל על אירועי אנליטיקה; אחר כך מודל מאומן אם יש נפח |
| **לא** | דירוג לפי `platform_percent` / מרג'ין (אסור יושרה ללקוח; SEARCH-UX) |

**תועלת:** המרה גבוהה יותר, פחות נטישה, שימוש חוזר.  
**עלות:** בינונית־גבוהה (דאטה, פיצ'רים, הערכת offline, חשש ל-bias).  
**סיכון:** המלצות "עשירות" מדי / פגיעה באמון אם נראה מניפולטיבי.

**תלויות:** ANALYTICS + consent; קטלוג יציב; מספיק אירועי redeem; אולי Meilisearch personalization קלה קודם.

---

### 1.2 מכרזים לספקים (placement / featured)

| | |
|---|---|
| **מה** | ספקים מתחרים על חשיפה (באנר בית, סלוט בקטגוריה, פוש עונתי) במחיר או באחוז תוספת מוגדר |
| **איך (MVP)** | מכרז ידני/לוח אדמין + חבילות חשיפה קבועות לפני אוטומציה מלאה |
| **כסף** | הכנסה נפרדת מפרסום; **לא** מבלבלים עם `platform_percent` של הדיל |

**תועלת:** הכנסה נוספת; ספקים חזקים מממנים צמיחה.  
**עלות:** בינונית (מוצר אדמין + חוזה + שקיפות ללקוח אם יש תווית "ממומן").  
**סיכון:** LEGAL/גילוי ממומן; ספקים קטנים מודרים; ניגוד עניינים אם הדירוג האורגני נעלם.

**תלויות:** ADMIN; SUPPLIER-PORTAL; LEGAL (גילוי פרסום); אנליטיקת חשיפה; SEASONAL ללוחות זמנים.

---

### 1.3 Live deals (דילים חיים / בזק משודר)

| | |
|---|---|
| **מה** | חלון קצר עם countdown, מלאי מוגבל, עדכון כמעט בזמן אמת בדף בית / קולקציה |
| **איך (MVP)** | הרחבה של SEASONAL + INVENTORY + countdown קיים; WebSocket/SSE רק אם polling לא מספיק |
| **לא** | countdown מזויף; שינוי מחיר אחרי תשלום |

**תועלת:** FOMO בריא, שיאי המרה בערב/חגים, תוכן לרשתות.  
**עלות:** נמוכה־בינונית אם נשענים על תשתית קיימת; גבוהה אם בונים realtime מלא.  
**סיכון:** עומס checkout; מלאי שנגמר ב-race; תלונות צרכן אם השעון משקר.

**תלויות:** SEASONAL-CAMPAIGNS; INVENTORY; PRICING (בזק); OBSERVABILITY; rate limit על checkout.

---

### 1.4 גיימיפיקציה

| | |
|---|---|
| **מה** | נקודות/משימות/סטריק קל: ביקור יומי, מימוש ראשון, חבר מביא חבר, תג "מיישם פעיל" |
| **איך (MVP)** | מעל REFERRAL + wallet credit פנימי; בלי NFT ובלי מטבע לסחורה |
| **כסף** | פרסים = זיכוי ארנק או קופון; תקרה ברורה מול FRAUD |

**תועלת:** שימור, DAU, ויראליות מתונה.  
**עלות:** בינונית (חוקי משחק, אנטי-fraud, UI).  
**סיכון:** ניצול בוטים; עלות קאשבק גולשת; רעש UI שמסיח מקנייה.

**תלויות:** REFERRAL-PROGRAM; CASHBACK-WALLET; FRAUD; LEGAL (לא הימור); NOTIFICATIONS.

## 2. טבלת עלות / תועלת (סיכום)

| פיצ'ר | תועלת עסקית | עלות בנייה | עלות תפעול | עדיפות אחרי soft-open |
|---|---|---|---|---|
| Live deals | גבוהה בטווח קצר | נמוכה־בינונית | בינונית | **1** |
| מכרזי חשיפה (ידני→אוטומטי) | הכנסה ישירה | בינונית | בינונית | **2** |
| המלצות (rules→ML) | המרה/שימור | גבוהה | בינונית | **3** (אחרי דאטה) |
| גיימיפיקציה | שימור | בינונית | בינונית־גבוהה (fraud) | **4** |

סדר מומלץ: Live → מכרז ידני → המלצות על דאטה → גיימיפיקציה מתונה.

## 3. מפת תלויות

```text
Analytics + Consent
        |
        v
   Live deals <---- Inventory + Seasonal + Pricing
        |
        v
 Supplier auctions (manual packs) <---- Admin + Legal disclosure
        |
        v
 Recommendations (rules) <---- enough purchase/redeem events
        |
        v
 Recommendations (ML)     Gamification <---- Referral + Wallet + Fraud
```

אין להתחיל ML לפני שיש חודשים של אירועים נקיים.  
אין גיימיפיקציה לפני ש-referral מיוצב מול אנטי-fraud.
