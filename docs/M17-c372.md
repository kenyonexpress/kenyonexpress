Measured 07.11.2026, 02:36 to 02:50 +07 (19:36 to 19:50 UTC on 06.11), against
`https://www.kenyonexpress.co.il`. Read-only: no code changed. `src/`,
`public/`, `messages/` and `supabase/` are unchanged since M17-c371
(`git diff 0a61d5963 HEAD` over them is 0 lines).

## Result

**No Hebrew text renders left-to-right on `/` or on 55 product pages, at 380,
768 or 1440. Unchanged since M17-c371, on a sample five pages wider.**

One complete pass of 168 loads (56 pages x 3 widths). All 168 answered HTTP 200
with their real `h1`; none showed the error screen. No navigation failed and no
retry was needed (each of the three instances ended with `navFailures=0
unmeasured=0`).

- `<html dir="rtl" lang="he">`, and `body` computes `direction: rtl`, 168 of 168.
- 0 visible elements whose own text contains Hebrew compute `direction: ltr`
  (88 to 197 Hebrew text elements per load).
- 0 Hebrew text elements compute `text-align: left`, or `start` under LTR.
- 0 elements get `direction: ltr` from CSS, other than the numeric discount
  badges on `/`.
- Horizontal overflow is 0 px on every load.
- All 168 loads printed `errors=0`: no console error, no `pageerror`, no
  response of 400 or above, and this time no cancelled image request either
  (M17-c371 had four in two loads).

Carried over from M17-c371:

- **The error screen of BACKLOG #26 did not appear.** `/product/מזקקת-ויסקי`
  rendered the product at all three widths, and no load had an `h1` of
  "משהו השתבש אצלנו": 0 of 171 loads (168, plus 3 control loads). The cause of
  the one occurrence in M17-c363 is still unknown and #26 stays open.
