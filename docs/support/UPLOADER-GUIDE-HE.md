# מדריך מעלה תוכן

Status: DRAFT · docs only  
Audience: `content_uploader` (וגם `admin` שמאשר)  
Admin: `https://kenyonexpress.co.il/admin`  
Companions: `docs/CONTENT-OPERATIONS-GUIDE.md`, `docs/product/PRODUCT-COPY-GUIDE.md`, `docs/ARCHITECTURE-AI-AGENTS.md`

עברית לטקסט ללקוח. שמות שדות באנגלית כמו בטופס. כסף: אגורות integer בקוד; בטופס מזינים ₪ והמערכת ממירה. אין float במסלול הכסף. אין Escrow. שיגור: קופון בלבד בסטטוס `active`.

סוכן AI (`catalog_enrichment`) כותב טיוטה בלבד. פרסום רק אחרי אישור אנושי.

---

## 0. סדר העבודה (א' עד ת')

1. הספק מוכן: שם, טלפון, כתובת, לוגו, חבר סורק אחד לפחות, `platform_percent` למוצר.
2. תמונות לפי סעיף 2 (לא picsum, לא צילום מסך מתחרה).
3. כותרת, תיאור, מחירים לפי `docs/product/PRODUCT-COPY-GUIDE.md`.
4. שמירה כ-`draft`. לא `active` בלי עיניים של מאשר.
5. אם משתמשים ב-AI: מאשרים או דוחים את `enrichment_suggestions` שורה-שורה.
6. מאשר (`admin`) מעביר ל-`active` רק אחרי הצ'קליסט בסעיף 5.

Chrome. לא טרמינל. אין `db push`. אין עריכת SQL על מוצרים חיים בלי מסלול האדמין.

## 1. פורמט CSV לייבוא טיוטות

הטופס הבודד ב-`/admin` הוא מסלול הפרסום. CSV הוא תור טיוטות למעלה: כל שורה = מוצר אחד ב-`draft`. פרסום המוני מ-CSV בלי אישור אסור.

קידוד: UTF-8 עם BOM אם Excel שובר עברית. מפריד: פסיק. שדות עם פסיק או שורה חדשה בתוך תא: מרכאות כפולות. כסף ב-CSV: **אגורות שלמות** (19900 = ₪199.00). אסור `199.5` כמחרוזת עם נקודה עשרונית בלי המרה מפורשת לפני טעינה.

### 1.1 כותרות חובה

| עמודה | חובה | הערה |
|---|---|---|
| `slug` | כן | אותיות קטנות, מספרים, מקפים. ייחודי |
| `name_he` | כן | 40 עד 60 תווים יעד. בלי מחיר, בלי אמוג'י |
| `name_en` | לא | `dir="ltr"` |
| `type` | כן | `coupon` בשיגור. `physical` / `recurring` רק טיוטה |
| `status` | כן | תמיד `draft` בייבוא |
| `supplier_id` | כן | UUID ספק קיים |
| `category_id` | כן | UUID מהעץ החי, לא `electronics` |
| `kenyon_price_agorot` | כן | שווי דיל / מחירון העסק באגורות |
| `coupon_price_agorot` | כן לקופון | מה שנגבה באתר |
| `platform_percent` | כן | אחוז פר-מוצר. מצולם ל-`order_items` בזמן הזמנה |
| `coupon_expiry_days` | כן לקופון | מספר שלם חיובי |
| `short_description_he` | כן | עד 300, יעד 140 עד 180. כולל משפט החובה |
| `description_he` | כן | 3 עד 6 משפטים |
| `highlights` | מומלץ | נקודות מופרדות ב-`\|` בתוך התא |
| `redemption_instructions_he` | כן לקופון | איפה, שעות, תיאום |
| `coupon_terms_he` | מומלץ | ימים מוחרגים, אין כפל |
| `seo_title` | לא | עד 60 יעד |
| `seo_description` | לא | עד 155 |
| `image_urls` | לא | URLs ציבוריים מופרדים ב-`\|`. עדיף העלאה בטופס |
| `alt_he` | כן אם יש תמונה | עברית, לפחות 3 תווים ואות עברית |
| `stock_quantity` | לא | שלם. בלי "נשארו 2" מזויף בטקסט |
| `sku` | לא | לטינית |

### 1.2 שורת דוגמה (מספרים דמה, לא מדיניות מחיר)

```
slug,name_he,type,status,supplier_id,category_id,kenyon_price_agorot,coupon_price_agorot,platform_percent,coupon_expiry_days,short_description_he
pasta-for-two-tlv,ארוחה זוגית עם קינוח אצל נונה בתל אביב,coupon,draft,00000000-0000-0000-0000-000000000001,00000000-0000-0000-0000-000000000010,39900,9900,15,90,"ארוחה זוגית כוללת מנה ראשונה, עיקרית וקינוח. משלמים ₪99 באתר. יתרה ₪300 בבית העסק במעמד המימוש. המחירים כוללים מע""מ."
```

### 1.3 בדיקות לפני טעינה

- `coupon_price_agorot` + יתרה = `kenyon_price_agorot`. יתרה = שווי פחות מחיר קופון.
- `coupon_price_agorot` > 0. אין "חינם" בטקסט אם המחיר גדול מ-0.
- אין שורת `type=physical` עם `status=active` בשיגור.
- אין עמודה `escrow`, אין הבטחת payout לספק במקדמה.
- קובץ בלי שורת כותרת נדחה.

אחרי טעינה: כל השורות `draft`. המעלה פותח כל כרטיס, מוסיף תמונות אמיתיות, לוחץ שמירה. רק אז תור האישור.

## 2. כללי תמונה

מסלול העלאה: `ImageUploader` בטופס האדמין, לא קישור חיצוני שבור.

| כלל | ערך |
|---|---|
| פורמטים | `image/jpeg`, `image/png`, `image/webp`, `image/avif` (GIF מתקבל בטופס; לא מומלץ לכרטיס) |
| משקל מקסימלי בטופס | 8MB |
| המלצה | עד 4MB, JPG או WebP |
| מינימום לתמונה ראשית | 800×800. מתחת: הכרטיס נמרח |
| יעד מקור | 1200×1200 עד 2000×2000. צלע ארוכה ≥1600 מועדפת לעיבוד שרת |
| יחס כרטיס | 1:1 בארכיון (נמדד ~186×186 דסקטופ, ~144.5 מובייל) |
| יחס צילום מומלץ | 4:3 או 3:2 לרוחב לחזית; הריבוע ב-CSS חותך |
| מספר תמונות | עד 8 למוצר |
| alt | עברית משמעותית. חובה אות עברית. לא `תמונה1`, לא שם קובץ |
| לוגו ספק | ≥400×400, רקע לבן או שקוף |
| אחסון | `products/<product_id>/<uuid>.<ext>` |

אסור: picsum, צילום מסך Groo / וואטסאפ / אתר מתחרה, מלל מחיר על התמונה שסותר את הקופה, פנים לקוח בלי הסכמה, סטוק של מקום אחר כאילו זה העסק.

כרטיס שיתוף OG הוא 1200×630 ונבנה ממחיר הקופון באתר, לא מהתמונה הריבועית כמות שהיא.

הודעה לעסק (להעתיק):

```
שלום, לצורך העלאת הדיל באתר צריך תמונות מהמקום עצמו (לא מאתר אחר).
3 עד 6 תמונות: חזית/שלט, המוצר או השירות, פנים המקום.
JPG מהטלפון, לרוחב, בלי זום דיגיטלי ובלי טקסט "מבצע 50%" על התמונה.
```

## 3. שימוש ב-AI (`catalog_enrichment`)

הסוכן קורא שם, סוג, תיאור גולמי ומאפיינים. כותב הצעה ל:

- `description_he`
- `short_description_he`
- `seo_title`
- `seo_description`
- `alt_he`

הפלט נשמר ב-`enrichment_suggestions` עם `status = pending_admin`. **לא מפרסם.** אין כלים לכסף. המודל לא רשאי להמציא מחיר, מלאי, שעות, או כתובת.

### 3.1 מתי להריץ

- יש שם עסק אמיתי ותמונה, והתיאור מהספק גולמי / חלקי.
- לא להריץ על מוצר בלי ספק, בלי מחיר, או עם `type` לא נכון.

### 3.2 איך לאשר

1. פותחים את ההצעה ליד הטיוטה.
2. בודקים משפט החובה לקופון:

```
משלמים ₪{coupon_price} באתר. יתרה ₪{יתרה} בבית העסק במעמד המימוש. המחירים כוללים מע"מ.
```

3. מוחקים טענות אסורות (סעיף 6 ב-`PRODUCT-COPY-GUIDE`).
4. מתקנים אורך SEO (כותרת ≤60, תיאור ≤155).
5. מאשרים: ההצעה נכתבת לכרטיס עדיין כ-`draft`.
6. רק מאשר אדמין מעביר ל-`active`.

Alt אוטומטי בלי עיניים: אסור ב-v1. אחרי מאות אישורים עם קבלה גבוהה יוחלט בנפרד.

### 3.3 מה ה-AI לא עושה

- לא משנה `coupon_price` / אגורות / `platform_percent`.
- לא ממציא QR, קוד קופון, או דירוג כוכבים.
- לא כותב "הכי זול", Escrow, "הספק מקבל את מה ששילמתם באתר".
- לא מפרסם `physical` בשיגור.

## 4. תור אישור (approval flow)

```
CSV או טופס  →  draft
        ↓
  (אופציונלי) catalog_enrichment → pending_admin
        ↓
  מעלה מתקן תמונה + מחיר + משפט חובה
        ↓
  admin מאשר  →  status=active, מופיע בקטלוג
        ↓
  דחייה  →  נשאר draft + סיבה בעברית למעלה
```

שער פרסום אנושי (גם אם הטופס נותן לשמור):

1. שלושת מחירי הקופון מתיישבים באגורות: קופון + יתרה = שווי.
2. משפט החובה קיים בתיאור קצר ומלא.
3. ספק: שם, טלפון, כתובת, לוגו, סורק.
4. alt בעברית על התמונה הראשית.
5. אין טענה אסורה.
6. קטגוריה מהעץ הסופי.
7. `platform_percent` לא ריק.
8. `type=coupon` לשיגור הציבורי.

הקפאה: `paused`. הסרה מהקטלוג בלי מחיקת היסטוריה: `archived`. מחיקת DB אסורה במסלול המעלה.

## 5. דחיות נפוצות (לכתוב בסיבת הדחייה)

| קוד קצר | למה נדחה | מה לתקן |
|---|---|---|
| `PRICE_MISMATCH` | קופון + יתרה ≠ שווי, או מחיר עם שבר לא ברור | שלושה מספרים באגורות, בדיקה בטופס |
| `MISSING_MANDATORY_SENTENCE` | חסר משפט "משלמים באתר / יתרה בעסק" | להדביק מהמדריך |
| `FORBIDDEN_CLAIM` | "הכי זול", חינם, Escrow, מלאי מזויף, דירוג מומצא | למחוק ולנסח מחדש |
| `IMAGE_STOCK_OR_COMPETITOR` | picsum / צילום מתחרה / מסך וואטסאפ | תמונות מהעסק |
| `IMAGE_TOO_SMALL` | מתחת 800×800 לתמונה ראשית | מקור חדש ≥1600 בצלע |
| `ALT_NOT_HEBREW` | alt באנגלית או `תמונה1` | משפט עברי על מה שרואים |
| `SUPPLIER_INCOMPLETE` | בלי כתובת / לוגו / סורק | להשלים עמוד ספק |
| `WRONG_TYPE_LAUNCH` | `physical` או `recurring` כ-`active` | להשאיר טיוטה |
| `SEO_TOO_LONG` | כותרת >60 או מטא >155 | לקצר; מחיר = קופון באתר |
| `TITLE_HAS_PRICE` | מחיר או "!!!" בשם | שם: מה מקבלים + עסק/עיר |
| `NO_REDEMPTION` | חסרות הוראות מימוש לקופון | שעות, כתובת, תיאום |
| `AI_UNEDITED` | טקסט AI עם מחיר מומצא / כתובת שגויה | עריכה אנושית לפני אישור |
| `DUPLICATE_SLUG` | slug תפוס | slug לטיני חדש |
| `CATEGORY_EMPTY_OR_LEGACY` | קטגוריה לא מהעץ החי | לפי `docs/product/CATEGORY-TAXONOMY.md` |

אין לאשר "כדי לזוז" אחרי שלוש דחיות מאותו מעלה בלי שיחת הדרכה.
