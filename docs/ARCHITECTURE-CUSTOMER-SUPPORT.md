## 2. מדיניות החזרים (Refunds)

### 2.1 עקרונות

1. נציג **פותח בקשה**; ביצוע כסף רק דרך `refund` server path / אדמין כספים (לא מהצ'אט ישירות בלי tool מאושר).
2. סכום ההחזר ≤ מה שנגבה באתר (Cardcom / ארנק), באגורות.
3. יתרה ששולמה בבית העסק **לא** מוחזרת דרך KE (הלקוח מול העסק).
4. כל החזר: `payment_events` / audit + הודעה ללקוח.

### 2.2 מטריצה

| מצב | החזר לכרטיס/ארנק דרך KE | הערות |
|---|---|---|
| הזמנה `pending` לא שולמה | לא רלוונטי | ביטול הזמנה |
| קופון כל ה-vouchers בסטטוס `issued` | כן (מדיניות + חוק) | בטל שוברים לפני/עם ההחזר |
| קופון לפחות אחד `used` (נסרק) | **לא** על החלק שמומש | חריגים רק אדמין+ספק בכתב |
| קופון `expired` שכבר זוכה לארנק (C6) | לא להחזיר שוב לכרטיס על אותו סכום | מניעת כפל |
| פיזי לפני `shipped` | כן בדרך כלל | תיאום מלאי עם ספק |
| פיזי אחרי `shipped` | לפי דין + תנאי ספק | RMA / תמיכה |
| כשל Cardcom / חיוב כפול | כן (SEV) | reconciliation |

### 2.3 מסלול תפעולי

```
Ticket → verify order_id + voucher statuses
  → classify (§2.2)
  → if allowed: admin runs refund action (Cardcom + ledger)
  → mark vouchers refunded/cancelled
  → notify customer (Resend)
  → close ticket with audit link
```

אסור לנציג להבטיח החזר שחורג מהמטריצה בלי אישור בעלים.

### 2.4 החזר חלקי בהזמנה מרובת שורות

הזמנה יכולה להכיל קופון + פיזי יחד. ההחזר הוא **פר שורת order_item**, לא פר הזמנה:

| כלל | פירוט |
|---|---|
| יחידת החזר | order_item (או תת-כמות ממנו) |
| סכום | `paid_on_site` של השורה בלבד, באגורות, מה-snapshot של השורה |
| ארנק שנוצל בהזמנה | מוחזר לארנק לפני החזר לכרטיס, באותו יחס שבו נוצל |
| ledger | תנועת החזר נרשמת מול השורה; פיזי: ביטול ה-commission של השורה בלבד |
| ההזמנה עצמה | נשארת paid אם נשארו שורות חיות; status פר שורה |

אסור: "החזר יחסי" מחושב ידנית במחשבון של נציג. הסכום נגזר רק מהערכים המצולמים על השורה.

### 2.5 Chargeback (הכחשת עסקה מול חברת האשראי)

| שלב | פעולה |
|---|---|
| קבלת הודעת chargeback מ-Cardcom | פתיחת טיקט SEV + הקפאת vouchers פתוחים של ההזמנה (`suspended`) |
| איסוף חבילת ראיות | order_id, timestamp תשלום, לוג webhook, voucher status, לוג סריקה אם מומש, אישור מייל שנשלח |
| מומש לפני ההכחשה | הראיה המרכזית: רשומת redeem עם זמן ומיקום העסק. הלקוח קיבל את התמורה |
| לא מומש | לשקול לוותר (accept) אם הסכום קטן מעלות הטיפול; ה-voucher מבוטל בכל מקרה |
| תוצאה | תיעוד ברישום: won / lost / accepted, והסכום |

לקוח שהגיש chargeback על voucher שמומש = דגל הונאה על החשבון (§5).

## 3. ביטול קופון (Cancel voucher)

| מצב voucher | ביטול אפשרי? | תוצאה |
|---|---|---|
| `issued` + בתוך מדיניות ביטול | כן | status → `refunded` או `cancelled`; כסף לפי §2 |
| `issued` אחרי תום חלון ביטול החוקי/החוזי | לפי legal.md | לעיתים זיכוי ארנק במקום כרטיס |
| `used` | לא (ברירת מחדל) | הלקוח מימש אצל הספק |
| `expired` | לא כ"ביטול"; כבר C6 ארנק אם רץ | |
| Replay redeem | לא מבטל; מסביר שכבר מומש | |

**חלון ביטול (יעד מוצר):** מיושר ל-`ARCHITECTURE-LEGAL.md` (למשל 14 יום לעסקאות מסוימות). התמיכה לא ממציאה חלון; מצטטת את המסמך החי.

ביטול יזום ע"י לקוח מ-`/account`: אופציונלי ב-soft-launch; עד אז רק דרך טיקט.

### 3.1 זיכוי ארנק כחלופה להחזר כרטיס

| כלל | פירוט |
|---|---|
| מתי מציעים | כשהחזר לכרטיס לא מתחייב לפי המטריצה אבל רוצים לשמר לקוח, או כשחלון הביטול החוקי עבר |
| הסכמה | הלקוח בוחר במפורש; זיכוי ארנק לא נכפה במקום החזר שמגיע לו בדין |
| סכום | עד `paid_on_site` של השורה; לא מוסיפים "בונוס" בלי אישור בעלים |
| כפל | voucher שזוכה לארנק מסומן כך; לעולם לא גם ארנק וגם כרטיס על אותו סכום |
| תוקף הזיכוי | לפי מדיניות הארנק (legal); שימוש באתר בלבד, אין משיכה |

## 4. מקרי שיחה נפוצים (מקרו)

| נושא | תשובת ליבה |
|---|---|
| "למה שילמתי רק X ולא את מלוא המחיר?" | X הוא מחיר הקופון באתר; היתרה משולמת בבית העסק בעת הסריקה |
| "מתי הספק מקבל את מה ששילמתי באתר?" | סכום האתר נשאר בפלטפורמה; הספק גובה את היתרה בעסק. אין Escrow |
| "הקופון לא נסרק" | בדיקת תוקף, סטטוס, ספק נכון; לא להנפיק קוד חדש בלי אדמין |
| "רוצה לבטל" | בדיקת סטטוס → מטריצת סעיפים 2 ו-3 |
| "הארנק" | קרדיט אתר בלבד; לא משיכה לבנק |

### 4.1 תבניות מקרו (נוסח מחייב, עברית)

**אישור פתיחת בקשת ביטול:**

```
שלום {שם},
קיבלנו את בקשת הביטול לקופון {מספר}. בדקנו ומצאנו שהקופון בסטטוס {סטטוס}.
{אם זכאי}: ההחזר בסך {סכום} ₪ יבוצע לאמצעי התשלום המקורי תוך {ימים} ימי עסקים.
{אם לא זכאי}: הקופון כבר מומש בבית העסק בתאריך {תאריך}, ולכן לא ניתן לבטלו.
צוות KenyonExpress
```

**הסבר מחיר קופון (השאלה הנפוצה ביותר):**

```
שלום {שם},
מחיר הקופון ששילמת באתר ({סכום} ₪) הוא התשלום עבור הקופון עצמו.
את היתרה בסך {יתרה} ₪ משלמים ישירות בבית העסק בעת המימוש, בהצגת הקוד.
שני הסכומים מופיעים בעמוד הקופון באזור האישי.
צוות KenyonExpress
```

**קופון לא נסרק אצל הספק:**

```
שלום {שם},
מצטערים על אי הנוחות. בדקנו את הקופון {מספר}:
{מקרה תקף}: הקופון תקף. פנינו לבית העסק והבהרנו; ניתן לממש שוב. אם הבעיה חוזרת, חזור אלינו מיד.
{מקרה מומש}: הקופון מומש בתאריך {תאריך} ולכן לא ניתן לסרוק אותו שוב.
{מקרה פג}: תוקף הקופון הסתיים בתאריך {תאריך}. {אם רלוונטי: זיכוי לארנק בוצע}.
צוות KenyonExpress
```

כל שינוי נוסח במקרו כסף = עדכון המסמך הזה, לא עריכה חופשית במערכת הטיקטים.
