# M14-c361: Sentry release matches HEAD

Measured 05.11.2026, 04:2x +07, against production `www.kenyonexpress.co.il`.

## Result

**The release tag matches HEAD on every runtime.** HEAD and the deployment
production serves are the same commit, and the client bundle has that SHA
baked in.

**Sentry has no release object for it.** The build's `sentry-cli releases new`
and `sourcemaps upload` both fail with `Invalid token (http status: 401)`. Events
carry the right `release` string, but Sentry has no release entity and no
source maps, so production stack traces stay minified. This is the same 401
recorded in M14-c111 (06.10) and BACKLOG #21. The fix is a new
`SENTRY_AUTH_TOKEN` in Vercel Production, with the `project:releases` and
`org:read` scopes, created in the Sentry UI. Every local copy of the variable
is the `[SENSITIVE]` placeholder (len 11), so no valid token exists on this
machine to swap in. That gap does not affect this item's check, which compares
the tag against HEAD.
