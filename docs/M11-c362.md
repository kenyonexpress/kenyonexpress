change, no production write, nothing deployed.

**Answer: yes to both, measured on production. This is the first run with the
site out of maintenance, so the check is against the live files and not a local
build.**

1. **Reachable: yes.** `www.kenyonexpress.co.il` serves the index and all five
   section files as `200 application/xml`, and all of them pass `xmllint`. All
   162 URLs listed in them return 200.
2. **Fresh: yes, an exact match.** Every active product, category and supplier
   in the production DB is in the sitemap, and nothing else is. The only rows
   left out are the four E2E fixtures, which are filtered on purpose. All 130
   `<lastmod>` values match `updated_at` to the millisecond.
3. **Still open, and now in effect on a live site: BACKLOG #23.** The sitemap,
   `robots.txt` and every canonical name the apex host
   (`https://kenyonexpress.co.il`), and the apex answers `308` to `www`. So the
   advertised sitemap URL and each of the 162 `<loc>` values reach their page
   through one redirect. Crawlers follow it, so nothing is unreachable, but
   Search Console reports such URLs as "Page with redirect". The fix is a Vercel
   env value or a domain swap plus a production rebuild, so it stays Ofir's.

### Edge cache

```
$ curl -sSI https://www.kenyonexpress.co.il/sitemap/products.xml   (twice, after the first fetch)
HTTP/2 200  age: 261  cache-control: public, max-age=0  x-vercel-cache: HIT
HTTP/2 200  age: 262  cache-control: public, max-age=0  x-vercel-cache: HIT
```

The route sets `s-maxage=3600, stale-while-revalidate=86400`
(`src/lib/seo/sitemap-response.ts`); Vercel consumes `s-maxage` and passes
`max-age=0` to the client. So an edit can take up to an hour to show at the
edge, on top of the `use cache` + `cacheTag(CATALOGUE_TAG)` layer that an admin
save refreshes immediately. The newest product edit (00:24 UTC) was already in
the file one hour later.
