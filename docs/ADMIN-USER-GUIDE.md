## 0. כללי כסף שחייבים לזכור

| כלל | מה עושים באדמין |
|---|---|
| אין עמלה קבועה | לא משאירים `platform_percent` ריק; אין "ברירת מחדל 5%" |
| קופון | הלקוח משלם באתר רק את מחיר הקופון; **הכל נשאר בפלטפורמה**; יתרה נגבית בעסק |
| פיזי | הלקוח משלם מחיר מלא; הפיצול לפי `platform_percent` |
| מנוי | חיוב חוזר לפי סכום מחזור; פיצול לפי `platform_percent` בכל חיוב |
| אין Escrow | אסור להבטיח לספק "שחרור מקדמה" על קופון |

סכומים במערכת: אגורות מאחורי הקלעים; במסכים מזינים **שקלים** (₪).

## 1. הוספת מוצר: קופון (שלב-שלב)

1. **ספקים** → ודא שהספק מאושר ומופיע ברשימה.
2. **מוצרים** → **מוצר חדש**.
3. סוג מוצר: **קופון**.
4. מלא:
   - שם בעברית, slug לטיני, קטגוריה, תיאור, תמונות
   - **מחיר דיל / ערך נקוב** (מה שהלקוח רואה כשווי)
   - **מחיר קופון באתר** (מה שנגבה בכרטיס)
   - **תוקף** (ימים או תאריך)
   - מלאי / מכסה לרכישה
5. **עמלת פלטפורמה (`platform_percent`)**: חובה למלא (לביקורת/דיווח; בקופון אין payout לספק מהאתר).
6. **חלק ספק (`supplier_split_percent`)**: משלים ל-100 עם עמלת הפלטפורמה.
7. **קאשבק %** (אופציונלי): אחוז מחיוב האתר ללקוח, לא מהערך הנקוב.
8. פרטי עסק לתצוגה ב-PDP: כתובת, טלפון, וואטסאפ, שעות, עיר, Waze.
9. שמירה כטיוטה → תצוגה מקדימה:
   - שולם באתר = מחיר קופון
   - יתרה בעסק = מחיר דיל − מחיר קופון
10. **פרסום** רק אחרי שכל שדות החובה ירוקים.

בדיקת קבלה מהירה:

- [ ] יתרה בעסק מוצגת ללקוח  
- [ ] אין טקסט "נאמן" / Escrow  
- [ ] מחיר קופון ≤ מחיר דיל  

---

## 2. הוספת מוצר: פיזי (שלב-שלב)

1. **מוצר חדש** → סוג **פיזי**.
2. מחיר מלא באתר (מה שנגבה בכרטיס).
3. **`platform_percent` חובה** (למשל 12 = 12% לפלטפורמה).  
   `supplier_split_percent` = 100 − platform.
4. מלאי, משקל/משלוח אם רלוונטי, זמן אספקה.
5. קאשבק % אופציונלי על הסכום שנגבה באתר.
6. שמירה → פרסום.

בדיקה:

- [ ] Publish נכשל בלי `platform_percent`  
- [ ] אחרי קנייה לדוגמה: בדוחות רואים snapshot של האחוז בשורת ההזמנה  

---

## 3. הוספת מוצר: מנוי (שלב-שלב)

1. **מוצר חדש** → סוג **מנוי**.
2. הגדר:
   - סכום לחיוב מחזור (`recurring_amount`)
   - מרווח: חודשי (ברירת מחדל)
   - מספר חיובים או ללא הגבלה
3. **`platform_percent`** לכל חיוב (אותו מנגנון פיצול כמו פיזי).
4. טקסט ביטול מנוי (קישור לאזור אישי).
5. פרסום רק אחרי בדיקת טוקן Cardcom / סביבת בדיקות.

שים לב: זיכויים ומנויים ארוכים תלויים בהגדרות מסוף Cardcom (מודול מנויים). ראה `CARDCOM-ARCHITECTURE.md`.

## 4. הגדרת `platform_percent` וקאשבק

### 4.1 platform_percent

| פעולה | איפה |
|---|---|
| יצירה / עריכה | מסך עריכת מוצר |
| מי רואה | אדמין בלבד (לא ללקוח כשדה עמלה) |
| אחרי קנייה | מצולם ל-`order_items`; **לא משנים רטרואקטיבית** |

טיפים:

- אל תעתיקו אחוז מספק אחר בלי בדיקה. כל דיל עצמאי.
- שינוי אחוז משפיע רק על הזמנות **חדשות**.

### 4.2 קאשבק

| שדה | משמעות |
|---|---|
| `cashback_percent` | אחוז מחיוב **האתר** (לא מערך נקוב של קופון) |
| זיכוי | נכנס לארנק פנימי אחרי תשלום מאומת |
| משיכה | אין; שימוש באתר בלבד |

השארה על 0 = בלי קאשבק למוצר.

## 5. ניהול ספקים

| משימה | מסך / פעולה |
|---|---|
| בקשות ממתינות | ספקים → בקשות → אישור / דחייה (עם סיבה) |
| פרטי בנק | חובה לפני payout פיזי; לא חוסם סריקת קופונים |
| עובדים | בעלים מוסיף `scanner` / `manager` |
| סניפים | ישויות משנה תחת אותו ספק |
| השעיה | אם חשד להונאה או הפרת הסכם |

מדריך צירוף מפורט לספק חדש:

```
docs/SUPPLIER-ONBOARDING.md
```

אסור להבטיח לספק תשלום מהפלטפורמה על מכירות קופון.

## 6. טיפול בהחזר

1. לקוח פונה דרך `/cancel` או תמיכה, או שאתה פותח מהזמנה באדמין.
2. בדוק:
   - האם בתוך 14 יום (לפי מדיניות / דין)
   - סטטוס שובר: `issued` / `redeemed` / `expired`
3. חשב דמי ביטול כשמותר: **הנמוך מבין 5% או 100 ₪** מסכום ששולם **באתר**. פגם/אי-אספקה → 0.
4. אשר החזר במסך האדמין (מפעיל את מסלול Cardcom בקוד).
5. ודא שהשובר לא ניתן לסריקה אחרי זיכוי.

אסור:

- לסמן `refunded` ב-SQL ידנית בלי סליקה  
- להחזיר ללקוח סכום שלא שולם באתר (יתרת עסק)  

פירוט תפעולי נוסף: `RUNBOOK-PRODUCTION.md`, `ARCHITECTURE-LEGAL-COMPLIANCE.md`.

## 7. קריאת דוחות

| דוח | מה מחפשים |
|---|---|
| מכירות יומיות | Gross אתר, מספר הזמנות, כשלי תשלום |
| לפי סוג מוצר | קופון מול פיזי מול מנוי |
| לפי ספק | מחזור; בקופון: הכנסת פלטפורמה מהאתר (לא "חוב לספק") |
| מימושים | סריקות היום; כפילויות / כשלים |
| Payout פיזי | יתרות payable אחרי T+N + שער משלוח |
| קאשבק | זיכויים מול מימוש ארנק |

טיפים:

- סינון לפי תאריך `paid_at`, לא לפי יצירת טיוטה.
- אם יש פער מול Cardcom: קודם reconciliation (GetLpResult), לא תיקון ידני בדוח.
