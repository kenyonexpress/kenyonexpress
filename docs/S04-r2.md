## Smoke: blocked

```
$ node scripts/r2-smoke.mjs --env-file=.env.vercel.production
REFUSED: R2_ACCESS_KEY_ID=absent
exit=2
$ vercel env pull <tmp>/.env --environment=production --yes
$ node scripts/r2-smoke.mjs --env-file=<tmp>/.env
REFUSED: R2_ACCOUNT_ID=placeholder R2_ACCESS_KEY_ID=placeholder R2_SECRET_ACCESS_KEY=placeholder R2_BUCKET_NAME=placeholder
exit=2
```

1. **The key pair can only be read inside Vercel.** `vercel env ls production`
   shows `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_ACCOUNT_ID`,
   `R2_BUCKET`, `R2_BUCKET_NAME` and `R2_ENDPOINT` as `Secret` (Hidden), all
   added in the last hour. A pull returns the `[SENSITIVE]` placeholder for each one.
   The only local copy (`.env.vercel.production`, 24.10) has no
   `R2_ACCESS_KEY_ID` at all, and its secret is 32 characters long. An R2 secret is
   64 hex characters and the access key id is 32, so that value is probably the
   id filed under the wrong name.
2. **The public URL host is not R2.** `R2_PUBLIC_BASE_URL=https://cdn.kenyonexpress.co.il`.
   The zone is Vercel DNS (`ns1/ns2.vercel-dns.com`), and the host answers with Vercel itself:
   ```
   $ curl -sI https://cdn.kenyonexpress.co.il/smoke/x.webp
   HTTP/2 404
   server: Vercel
   x-vercel-error: DEPLOYMENT_NOT_FOUND
   ```
   So even a successful PutObject would curl 404. An R2 custom domain needs
   the zone on Cloudflare. Without that, the bucket's `r2.dev` public URL has to
   be enabled in the Cloudflare dashboard and `R2_PUBLIC_BASE_URL` pointed at it.

I did not add a production endpoint just to run this smoke with the
deployment's own env. It would be a credential-gated write path to production,
and because of item 2 its GET still could not return 200.

**To close it:** put the R2 key pair in the shell (or in a local env file),
fix item 2, and then run:

```
node scripts/r2-smoke.mjs --env-file=<file with real R2_* values>
```

It exits 0 only when every variant answers 200 with its own `image/*` type.
