`https://www.kenyonexpress.co.il`. Read-only: no code changed. `src/`,
`public/`, `messages/` and `supabase/` are unchanged since the M17-c378 base

## Result

**No Hebrew text renders left-to-right on `/` or on the five sampled product
pages at 380, 768 or 1440. Unchanged since M17-c379.**

Two full passes of 18 loads (6 pages x 3 widths), both on HEAD's deployment,
both with 0 leaks on every load, and line-for-line identical in every RTL
count:

- `<html dir="rtl" lang="he">`, and `body` computes `direction: rtl`, 36 of 36.
- 0 visible elements whose own text contains Hebrew compute `direction: ltr`
  (90 to 197 Hebrew text elements per load).
- 0 Hebrew text elements compute `text-align: left`, or `start` under LTR.
- 0 elements get `direction: ltr` from CSS, other than the 20 numeric discount
  badges on `/`.
- Horizontal overflow is 0 px on every load.
- 36 of 36 loads: HTTP 200 with the real `h1`. 0 failed navigation attempts,
  0 unmeasured, 0 error screens.
- Pass 1: 18 of 18 loads `errors=0`. Pass 2: 17 of 18 `errors=0`; the one
  exception is a single `net::ERR_ABORTED` on the logo `/_next/image` request
  on `מלון-4-כוכבים-פלוס-ארוחת-בוקר` at 1440, a client-side cancel with no HTTP
  status (the same transient seen in M15-c380 and earlier cycles), recorded
  after the page had loaded with status 200 and the real `h1`. The RTL counts

## What computes LTR, and why each is not a text leak

| What | Where | Count | Text inside | Verdict |
|---|---|---|---|---|
| `span.discount_per`, `direction: ltr` from CSS | `/` only | 20 per load | `-NN%`, no Hebrew (the probe checks the text of each one) | Deliberate. LTR keeps the minus sign before the number. |
| `a[dir="ltr"]` supplier phone link | 4 of 5 product pages (none on the Samsung page) | 1 each | `052-4635550` (2 pages), `972524635550` (2) | Deliberate. A phone number is Latin digits. |
| `input[type=email][dir="ltr"]`, footer newsletter | every page, visible at 1440 | 1 | Hebrew placeholder `הזן כתובת אימייל`, `text-align: start` | Known exception, BACKLOG #25. Not changed: `src/components/layout` is frozen. |

The set of `dir="ltr"` elements on each page is the same at all three widths
and in both passes.

## Probe

`/tmp/m17-c380/work/probe.cjs` (Playwright Chromium, locale he-IL, not
committed). It is M17-c379's probe with one change: the output directory in
the error-screen screenshot path (`sed` over the `/tmp/m17-c379` prefix,
`diff` shows that one line). The checks and the navigation retry are untouched.

Each page loads, waits 3 s, then scrolls 10 x 1200 px so lazy sections mount.
It walks every element in `body` outside `svg` (349 to 967 per load).
Requests to PostHog were aborted so the probe stays out of product analytics.
Each pass ran the 6 pages in one Chromium instance; pass 1 took 4.3 min
(09:39:00 to 09:43:17), pass 2 took 4.5 min (09:43:36 to 09:48:07).
