## Result

1440.** Four passes of 22 page loads each, 88 loads in all. 85 loads are
clean on every error count. The other three loads carry only Chromium
transport errors from the probing Mac's own connection

## The three loads with transport errors

**Pass 1, `/product/demo-restaurant` at 1440 (10:5x UTC).** 27 console
errors, 1 `pageerror`, 25 failed requests, all from the Mac's connection
going away while the page was loading:

```
  14 console: Failed to load resource: net::ERR_NAME_NOT_RESOLVED
   8 console: Failed to load resource: net::ERR_NETWORK_CHANGED
   3 console: Failed to load resource: net::ERR_FAILED
   1 console: ChunkLoadError: Failed to load chunk /_next/static/immutable/chunks/0t6je-glfa2na.js from module 522686
   1 console: app error boundary:  ChunkLoadError: Failed to load chunk /_next/static/immutable/chunks/0t6je-glfa2na.js ...
   1 pageerror: Failed to load chunk /_next/static/immutable/chunks/012al65fxm4lu.js from module 628400
  13 requestfailed: fetch  net::ERR_NAME_NOT_RESOLVED  (RSC prefetches: /contact, /category/restaurants-cafes, /product/demo-*, /monitoring ...)
   5 requestfailed: script net::ERR_NETWORK_CHANGED    (two /_next/static/immutable/chunks/*.js, two Vercel script.js)
   3 requestfailed: fetch  net::ERR_NETWORK_CHANGED    (RSC prefetches: /login, /, /account/wishlist)
   3 requestfailed: script net::ERR_FAILED             (the same chunks, retried)
   1 requestfailed: other  net::ERR_NAME_NOT_RESOLVED  (/images/logo.webp)
```

The HTML had already arrived (HTTP 200 and `imgs=11` on the paired 380
load seconds earlier), two script chunks never arrived, and the app's
error boundary rendered its fallback with the `ChunkLoadError` logged once
by Next and once by the boundary's own `console.error` (`app error
boundary:` prefix). That is the designed path for a chunk that cannot be
fetched; it is the first time an M15 run has caught it on a real load.

**Pass 3, `/product/launch-italian-dinner-tlv` at 1440 (11:0x UTC).** 17
console errors and 17 failed requests, same two Chromium codes plus
`ERR_FAILED` on the retries; the page had already rendered its `<h1>` and
all nine images before the drop, so no `pageerror` and no boundary:

```
   8 console: Failed to load resource: net::ERR_NAME_NOT_RESOLVED
   6 console: Failed to load resource: net::ERR_NETWORK_CHANGED
   3 console: Failed to load resource: net::ERR_FAILED
   6 requestfailed: ... net::ERR_NETWORK_CHANGED   (two chunks, four RSC prefetches)
   8 requestfailed: fetch net::ERR_NAME_NOT_RESOLVED (RSC prefetches)
   3 requestfailed: ... net::ERR_FAILED             (two chunks retried, one woff2 font)
```

**Pass 4, `/product/demo-restaurant` at 380 (11:1x UTC).** One console error
and one failed request, a single script chunk on a connection whose HTTP/2
ping timed out; the page rendered fully (`<h1>`, 11 images, 0 broken):

```
   console: Failed to load resource: net::ERR_HTTP2_PING_FAILED
   requestfailed: script net::ERR_HTTP2_PING_FAILED .../_next/static/immutable/chunks/3lqaolumq879g.js
```

`ERR_NETWORK_CHANGED` is Chromium's own signal that the host's network
configuration changed while requests were open; `ERR_NAME_NOT_RESOLVED` for
`www.kenyonexpress.co.il`, a name that resolved for the loads on either side
of each drop, is the local resolver losing its upstream for a moment;
`ERR_HTTP2_PING_FAILED` is Chromium abandoning an idle HTTP/2 connection
whose keep-alive ping went unanswered. None is an HTTP response from the
site; the probe's `http4xx5xx` column is 0 on all 88 loads. All six chunks
that failed in these three loads answer 200 afterwards from the same host:


The Mac's unified log (`log show`, `com.apple.network`, `configd`,
