## The role model as deployed

- **admin / super_admin** — `is_admin()`; write surface on catalogue, orders,
  growth, payouts. Role changes are gated by the 181 ladder in
  `enforce_profile_privilege_columns()`: no self change, admin-tier
  grants/revocations only by super_admin, super_admin writes only on an aal2
  (MFA) JWT, plus the RESTRICTIVE `profiles_super_admin_mfa` policy.
- **support** — `is_support()`; curated operational SELECT surface, no writes.
- **read_only (the viewer tier)** — added by 181; `is_support()` includes it,
  so it inherits support's whole SELECT surface, and it appears in **no**
  write policy and no staff branch: read-only by construction at the DB layer.
- App layer mirrors this in `src/lib/admin/roles.ts` (`isAdminRole` /
  `isSupportRole` / `isStaffRole` / `isPanelRole`), the section matrix in
  `permissions.ts`, and the guards in `rbac.ts`. As of this goal the proxy's
  optimistic panel check also admits `read_only`, and the `AppRole` alias is
  retired — the generated `UserRole` carries all seven values.

## Policy audit by table class

All 200+ policies were dumped (`pg_policies`) and read. Classes:

1. **Deny-all server-only tables** (RESTRICTIVE `false` for anon+authenticated;
   service role only): `rate_limits`, `user_rate_limits`, `referral_signals`,
   `search_index_outbox`, `search_index_dlq`, `settlement_events`,
   `stock_reservations`, `stock_waitlist`, `scheduled_price_changes`,
   `coupon_redemptions`, `legacy_percent_archive_112`.
2. **Admin-read-only tables** (`is_admin()` SELECT, no client writes):
   `abandoned_cart_nudges`, `ai_usage`, `analytics_events`, `audit_log` (plus
   explicit no-insert/update/delete `false` policies), `coupon_qr_*`,
   `discount_campaigns`, `email_suppressions`, `notification_outbox`,
   `payment_webhook_events`, `referral_program_settings`, `report_*` (4),
   `whatsapp_outbox`.
3. **Owner-scoped tables** (`auth.uid()` equality, usually + admin/support
   read): profiles, orders/order_items (+ supplier-member branch), payments,
   payment_tokens, refunds, invoices, wallet_*, cashback_ledger, vouchers,
   subscriptions, addresses, wishlists, notifications, push_*,
   webauthn_credentials, support_tickets (+ staff read/update), whatsapp
   contacts/inbound, searches, coupon_codes, discount/voucher redemptions.
4. **Public catalogue** (anon SELECT on active+not-deleted rows; writes
   admin/content_uploader): products, product_variants, product_images,
   categories, suppliers, supplier_branches, banners, homepage_sections,
   coupons, coupon_deals, cashback_rules, reviews (approved), seo_redirects,
   pickup_points, shipping_zones, price_history, popular_searches,
   media_assets.
5. **Tenancy (suppliers)** — separate axis on `supplier_members` via
   `is_supplier_member()/is_supplier_owner()`; vendors table writes are
   super_admin-only.

No policy grants a write to `support` or `read_only` anywhere; no
`USING (true)` write policy exists; the three `USING (true)` SELECTs
(media_assets, price_history, shipping_zones) are deliberate public catalogue
surface.

## Gaps found and closed in this audit (migration 212, applied)

1. **TRUNCATE was grantable past RLS.** RLS gates SELECT/INSERT/UPDATE/DELETE
   only; the Supabase bootstrap `GRANT ALL` had left `authenticated` with
   TRUNCATE on 72 tables including orders, payments and audit_log. No client
   path truncates (measured: zero occurrences), PostgREST exposes no TRUNCATE
   verb — defence in depth, revoked wholesale plus default privileges for
   future tables.
2. **Three functions ran with role-mutable `search_path`** (advisor 0011):
   `set_updated_at`, `fn_cashback_ledger_block_mutation`,
   `fn_il_phone_digits`. Pinned to `public`. Advisor now clean.

## Intentional exceptions (do not "fix")

- **`media_ingest_queue`, RLS on + zero policies** (advisor INFO): 210's
  documented design — written only by the ingest script via service role,
  client grants revoked in the same file. Zero policies *is* deny-all here.
- **`carts` anon DML**: guest carts keyed by session cookie; the owner-all
  policy scopes every row. Revoking it breaks guest checkout.
- **`is_admin()` / `is_supplier_member()` anon EXECUTE** (advisor 0028): both
  are called inside `USING` clauses of policies that anon evaluates
  (suppliers, seo_redirects, categories, product_images…). Anon needs EXECUTE
  for those policies to run at all; both return false for anon and leak
  nothing.
- **21 authenticated-executable SECURITY DEFINER functions** (advisor 0029):
  measured one by one — every `admin_*`/payout/cashback function checks
  `is_admin()` internally and raises otherwise; `redeem_voucher`,
  `verify_supplier_staff_pin`, `supplier_app_context`, `has_role`,
  `current_user_role` are caller-scoped by `auth.uid()` by design.
  `check_rate_limit` EXECUTE is already revoked (145, live).

## Service-role containment (app layer)

`createAdminClient()` (`src/lib/supabase/admin.ts`) is the single service-role
factory. It runs in server actions, route handlers (webhooks + cron), server
components and `src/lib`/`src/server` modules — never in anything a browser
bundle can reach. Enforced from this goal onward by
`src/lib/supabase/admin-server-only.test.ts`: no `'use client'` file and
nothing under `src/components/` may import the admin module or name the
service-role env vars, and raw env reads are pinned to a four-file allowlist.
The action-layer guarantee (`auth-coverage.test.ts`: every exported action
carries a guard or a stated public reason) and the route guarantee
(`route-guards.test.ts`) were green before and after this goal.
