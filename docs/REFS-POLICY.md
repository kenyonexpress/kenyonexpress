# refs/ policy

**Recommendation: change nothing. Do not adopt git-lfs, and do not commit the
screenshots.** The reasoning is below, and the premise it corrects matters more
than the conclusion.

Measured 2026-09-06.

## The premise this was raised on is not true

The instruction was: *"Do not add `refs/*.png` to gitignore. Those screenshots
are the measurement baseline the parity gate compares against; excluding them
breaks the gate on any fresh clone."*

Two things are wrong with that, and both are checkable.

**1. `refs/` has been gitignored the whole time.** `.gitignore:57` is a bare
`refs/`, with a comment saying it covers `refs/*.png` deliberately. Nothing was
added; this is the state the gate has always run in.

**2. The screenshots are the gate's OUTPUT, not its input.** `scripts/compare.mjs`
takes both screenshots itself on every run — it loads the **live site over the
network** and our local build, and writes `refs/live.png` and `refs/mine.png`.
`scripts/diff-bands.mjs` then reads the two files that run just produced:

```js
const liveUrl = toDataUrl(process.env.COMPARE_LIVE_PNG ?? 'refs/live.png')
const mineUrl = toDataUrl(process.env.COMPARE_MINE_PNG ?? 'refs/mine.png')
```

There is no committed baseline to compare against. A fresh clone with an empty
`refs/` runs the gate correctly, because the first thing the gate does is create
what it needs. Committing yesterday's PNGs would not help it and would risk the
opposite: `diff-bands.mjs` already carries a warning about a stale `pnpm start`
serving an old build and reporting 45.53% — a stale committed screenshot is that
same failure with a longer half-life.

## What is actually in refs/

305MB on disk, of which:

- **Generated per run** — `live*.png`, `mine*.png`, band and diff JSON. Recreated
  by `compare.mjs` and worthless the moment the page changes.
- **Captures** — `ke_live_*.html` (live's markup), `ke_live_computed.json`
  (5.8MB), `electro_home.html`, `electro_shop.html` and their computed dumps.
  These ARE inputs, to token provenance and geometry work, but not to the gate.
  Regenerated by `scripts/capture-electro.mjs` and the live capture scripts.
- **Nine tracked files**, which the ignore does not cover because they were
  committed before it: `refs/PRODUCT-PAGE-SPEC.md`,
  `refs/electro-checkout-text.json`, `refs/ke-checkout-measured.json`,
  `refs/measure-cart-checkout.json`, `refs/measure-cart-checkout.mjs` and four
  others. Small, hand-written or hand-measured, and correctly kept.

## Why not git-lfs

- **It solves a problem this repo does not have.** LFS is for large files that
  must be versioned. These are large files that must be *regenerated* — a
  screenshot of a page that has since changed is not a version of anything, it
  is a stale measurement.
- **It costs on every clone.** LFS pulls on checkout by default, so every fresh
  clone and every CI job would fetch hundreds of megabytes of screenshots that
  the next `compare.mjs` run immediately overwrites.
- **It adds a failure mode.** An LFS pointer that did not resolve looks like a
  corrupt PNG, and the gate would report a diff percentage against it rather
  than an error. This project has already been bitten once by a gate confidently
  measuring the wrong thing.

## Why not a pruning policy either

There is nothing to prune on a schedule. The generated half is overwritten every
run and the capture half is small relative to it. If `refs/` ever becomes a real
problem, the honest fix is `rm -rf refs/*.png` and re-running the gate, which
costs one gate run and no history.

## The one thing worth doing, and it is not urgent

The nine tracked files under `refs/` sit inside an ignored directory, which is
confusing: `git status` will never show a change to them, so an edit is easy to
lose. Moving them to `docs/measurements/` would put hand-authored measurements
where hand-authored things live and leave `refs/` purely generated.

**Not done here**, because it is a rename touching paths that tests and docs
reference, and this document was asked to recommend rather than to act.

## 2026-09-08: the reference the gate compares against no longer exists

Added in maintenance pass 42, after measuring rather than reasoning.

`kenyonexpress.co.il` stopped serving WordPress. The DNS was cut to Vercel and
the host serves **this application**. So `compare.mjs`, left pointing at the
network, measured the local build against our own production deployment and
still printed a percentage: **39.76% at 380px**, with the height-ratio guard
firing at 1.80x. A fidelity score against yourself is worse than no score,
because it looks like a score.

### The snapshot is not a replacement, and the shortfall is fonts

The default is now `refs/localized/*.html`, snapshots taken while the site was
live, rewritten by `scripts/localize-live-refs.mjs` to resolve imagery from
`refs/live-assets/`. Loading the localized home page in Chromium:

```
49 images, 0 broken          <- the localizer works
96 failed requests           <- every one a font
```

Open Sans and two Font Awesome families still point at
`kenyonexpress.co.il/wp-content/`, which 403s. **They cannot be recovered.**
`refs/live-assets/` contains no `.woff`, `.woff2` or `.ttf` at all - the archive
captured imagery and not typefaces - and the origin that served them is gone.
The reference renders in fallback type with tofu where the icons were.

Three figures now exist for home at 380 and none is interchangeable with
another:

| figure | what it compared |
| --- | --- |
| 10.68% | the real WordPress site, while it was live |
| 39.76% | our build against our own production |
| 30.26% | our build against a snapshot missing its fonts |

**The 11% gate in `CLAUDE.md` refers to the first.**

### How much the missing fonts actually cost: about one point (pass 59)

The paragraph that used to sit here said 30.26% should be read as a floor
"rather than as a failure against that ceiling", which implied the font loss
explained a large part of it. **Measured across all three widths on one build,
it does not.**

```
width   localized reference   historical, live site   delta
 380          30.26%                 10.68%           +19.6
 768          28.99%                 -                 -
1440           8.29%                  7.08%            +1.2
```

`1440` is the one width where a historical figure exists for home, and the
degraded reference costs **1.2 points** there. A reference that costs one point
at desktop cannot be costing twenty at mobile.

So the mobile numbers are very largely REAL divergence, and it is already
recorded: KNOWN-ISSUES #3, "mobile layouts diverge structurally from live, a
layout project, not a tuning pass". The snapshot is not what makes 380 read 30%.

**And 1440 passes the gate at 8.29%** - on a reference known to be missing its
fonts, which makes it a conservative pass rather than a generous one.

### The trap that was armed, and is now disarmed

The first version of the snapshot default ended `?? networkUrl`. `refs/` is
gitignored in full, so `refs/localized/` cannot exist on a CI runner, and that
fallback would have quietly sent the gate back to the network. The `pixel-gate`
job skips today only because `CI_SUPABASE_URL` is unset - and setting it is an
open MANUAL item. The trap was set to spring on the day someone did the thing
they are being asked to do.

`REFERENCE()` now throws with the reason instead. `COMPARE_USE_NETWORK=1` still
opts in explicitly, for the day the reference is hosted somewhere real.

### What the owner could decide

Nine files under `refs/` are already tracked past the ignore rule, so
force-adding `refs/localized/` is possible: 2.7 MB of HTML, which would let the
gate run on a runner. `refs/live-assets/` is another 13 MB and would be needed
with it. That is a deliberate exception to this document's own rule that `refs/`
is generated, so it is recorded here as an option and not taken.
