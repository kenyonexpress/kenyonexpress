## The link

Measured from this machine with no throttling:

```
$ curl --compressed https://www.kenyonexpress.co.il/  (3 fetches, 12:10Z)   connect 0.26-0.34 s, ttfb 1.18-1.26 s
$ curl --compressed https://www.cloudflare.com/       (3 fetches, 12:10Z)   connect 0.24-0.59 s, ttfb 0.92-1.11 s
$ curl --compressed https://www.kenyonexpress.co.il/  (3 fetches, 12:16Z)   connect 0.27-0.61 s, ttfb 0.99-1.32 s
$ curl --compressed https://www.cloudflare.com/       (3 fetches, 12:16Z)   connect 0.24-2.48 s, ttfb 0.75-3.43 s
$ curl LCP image, logo.webp, robots.txt, /            (3 fetches each, 12:17Z)   connect 0.24-0.51 s, ttfb 0.93-1.37 s, all 200, all x-vercel-cache: HIT
```

One fetch of an unrelated host took 2.5 s to connect and 3.4 s to first byte at 12:16Z, the same size of stall c366 recorded once. A quarter of a second to connect and about a second to first byte on an unthrottled fetch is the floor this link gives any live run, and it stalls for seconds now and then. That fits the `/` runs, but it is a fit, not a proof: no stall was caught during a Lighthouse run itself. Supabase was not timed directly; the build had 0 timeouts.
